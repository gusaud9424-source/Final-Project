# 개념 설명 문서화 프롬프트

> 용도: 작업 폴더(docs/learning/<폴더>)마다 "개념 설명" 문서를 추가할 때 사용
> 기준 예시: docs/learning/Sandbox 격리점검/02_Sandbox_격리_개념설명.md, docs/learning/보상 UI 정리/09_보상구조_개념설명.md

```
[개념 설명 문서 작성]

■ 대상 폴더
- docs/learning/<폴더명>
- 폴더 안 기존 문서(01, 02 …)와 관련 코드를 먼저 모두 읽고, 실제 코드 기준으로 작성할 것

■ 파일
- 같은 폴더에 <다음 번호>_<주제>_개념설명.md 로 저장
- 기존 문서는 수정하지 않고, 각 문서의 "> 작성:" 줄 아래에 메모 한 줄 추가
  > 📘 개념 설명(용어·코드 의미·최종 구조)은 `<새 문서명>` 참고.

■ 독자
- 웹·보안을 처음 배우는 입문자(작성자 본인 포함). 발표에서 그대로 설명할 수 있어야 함
- "핵심만 짧게"가 아니라 "핵심을 상세하고 적당하게": 왜 → 무엇 → 어떻게 → 없으면 생기는 일 순서

■ 문서 구성 (순서 고정)
1. 요약 – 기능이 무엇이고 왜 만들었는지, 최종 구조 5~7줄
2. 개념 설명 (비유) – 전체 구조 그림(ASCII) + 일상 비유, 핵심 문장의 정확한 의미 풀이
3. 용어 설명 – 문서에 나오는 단어를 빠짐없이 표로 (영어 약어·코드 이름 포함)
4. 구조와 코드 – 핵심 코드 발췌 + 각 줄 의미 + "없으면 생기는 일" 표, 관련 파일 표
5. 동작 흐름 – 사용자 행동부터 결과까지 단계별 예시
6. 주의점과 한계 – 남은 위험, 아직 안 된 것, 오해하기 쉬운 점
7. 핵심 정리 – 요점 + 발표용 한 문장
8. 검증 (이 문서의 근거) – 참고한 코드 파일, 기존 문서의 확인 기록

■ 작성 원칙
- 쉬운 말 우선, 전문 용어는 처음 나올 때 바로 풀어서 설명
- 코드는 실제 코드에서 발췌(요약 시 "(요약)" 표기), 추측으로 쓰지 않기
- 숫자(금액·제한값·HTTP 상태코드 등)는 코드 값과 일치시키기
- 표 · 그림(ASCII) · 비유를 적극 활용
- 공격 입력값이나 우회 방법은 쓰지 않음 (방어·구조·원리 중심)
- 문서 끝: *© 2026 5팀_Security Learning Platform (부트캠프 캡스톤 학습용)*

■ 대상 폴더 목록 (진행 순서)
1. 보상 UI 정리 ✅
2. 난이도 학습 구조 ✅
3. 진도율 설정 ✅
4. 출석 체크와 포인트 지급 ✅
5. 관리자 회원관리 ✅
6. 수강취소 ✅
7. 과목 상세 탭 보완 (보류 — 필터로 중단)
8. 자료실 PDF ✅
9. 로고변경 ✅
(Sandbox 격리점검 ✅, 실습페이지 구성은 제외)
```
