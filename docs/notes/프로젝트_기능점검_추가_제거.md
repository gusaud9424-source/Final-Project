## 2. 🔴 꼭 넣어야 할 것 (발표 전 권장)

| # | 항목 | 현재 상태 (확인 근거) | 왜 필요한가 | 작업 크기 |
|---|---|---|---|---|
| 1 | **회원가입 실제 연동** | 화면은 있지만 `stores/auth.js` 의 `signup()` 이 **mock**(가짜 성공 메시지)이고, 백엔드에 회원가입 API 가 없음 | 새 학생이 가입할 수 없다. 데모 계정으로만 시연 가능. "가입 완료" 라고 나오는데 실제로는 계정이 안 생겨 오해 소지 | 중 (API + bcrypt 저장 + 중복 검사 + Rate Limit) |
| 2 | **README 작성** | `README.md` 가 **1줄**뿐 | 프로젝트 지침상 **Attribution(출처) 섹션 필수**. 실행 방법·구조·계정 안내가 없으면 평가자가 실행할 수 없음 | 소 |
| 3 | **개념 확인 문제 문항** | `concept_check.py` 비어 있음 → "준비 중" | 비어 있으면 1회차를 완료할 수 없어 **진도율이 최대 67%**, 미션 보상도 못 받음 | 소 (과목별 5문항 직접 작성) |
| 4 | **보안 응답 헤더 (Nginx)** | `nginx.conf` 에 `Content-Security-Policy` · `X-Frame-Options` · `X-Content-Type-Options` 없음 | 팀이 직접 돌린 ZAP 진단에서 **CSP 미설정 · 클릭재킹 방어 헤더 누락**이 위험도 중간으로 나왔음. 보안 학습 플랫폼이 자기 서비스에 이 헤더가 없으면 발표 질문 대상 | 소 (단, 실습 iframe 이 깨지지 않게 실습 경로는 예외 처리 필요) |
| 5 | **404 페이지** | `NotFoundView.vue` 가 "404 — 페이지 없음 / 경로" 만 있는 **임시(stub)** 화면 | 잘못된 주소에서 디자인이 깨진 화면이 보임. 대시보드로 돌아가는 버튼 필요 | 소 |

## 3. 🟡 넣으면 좋은 것 (여유 있을 때)

| # | 항목 | 현재 상태 | 설명 |
|---|---|---|---|
| 6 | 휴대폰 아이디 찾기 | `sendFindIdPhoneCode` · `verifyFindIdPhoneCode` 가 **mock** | 이메일 방식은 실제 동작. 휴대폰 방식은 화면만 있음 → 연동하거나, 메뉴를 숨기거나 "준비 중" 표시 |
| 7 | HTTPS | Nginx 가 `listen 80`(HTTP)만 | 프로젝트 지침엔 HTTPS 가 있음. 로컬 시연은 HTTP 로 충분하지만, 발표에서 "운영 시 HTTPS + Secure 쿠키"를 계획으로 언급 권장 (`SESSION_COOKIE_SECURE` 는 운영 모드에서만 켜짐) |
| 8 | 감사 로그 보관 | `[AUDIT]` 를 서버 로그에만 기록 | 컨테이너 로그가 지워지면 사라짐. 테이블 저장 또는 파일 로그로 보관하면 관리자 기능 신뢰도 상승 |
| 9 | 로그인 실패 기록 | 로그인은 Rate Limit(분당 10회)만 | 실패 기록(감사 로그)을 남기면 무작위 대입 시도를 관리자가 확인 가능 |
