# 01. 과목 상세 탭 보완 (실습 · 미션 · 과목 정보)

> 대상: 웹 보안을 처음 배우는 입문자
> 목표: 과목 상세 화면의 세 탭이 각각 어떤 내용을 보여주고, 미션 보상을 어디서 받게 바뀌었는지 이해한다.
> 작성: 2026-10-04 · 오현명

---

## 1. 요약

- **실습 탭**: 실습 목적 · 왜 배우나 · 실습 화면 · 진행 방법(단계) · 팁을 안내 카드로 보여준다.
- **미션 탭**: "내 제출물"과 날짜를 빼고 미션 설명을 네모 칸에 담았다. 오른쪽 보상 영역을 설명과 같은 높이로 정렬했다.
- **보상 분리**: 미션(방어 퀴즈) 보상만 미션 탭에서 받고, 실습 등 나머지 보상은 **헤더 보물상자**에서 받는다(보물상자는 유지).
- 실습·미션 보상 모두 과목 난이도에 따라 **경험치 또는 포인트 중 하나만** 지급된다(초급=경험치, 중급·고급=포인트).
- 미션 카드의 이동 버튼(실습 하러 가기 · 퀴즈 풀기 등)은 제거했고, 개념 학습은 완료 시 "보상 완료"로 표시한다.
- 미션 설명 텍스트를 키우고 세로 가운데 정렬했으며, 왼쪽 설명과 오른쪽 보상 영역의 높이를 맞췄다.
- **과목 정보 탭**: 취약점 설명 · 비유 · 영향 · 방어 · 공격 예시를 입문자용으로 보완했다.

---

## 2. 개념 설명 (비유)

요리 교실의 **레시피 카드 세트**와 같다.

- 실습 탭 = "오늘 뭘 만들고, 왜 만들고, 어떤 순서로 만드는지" 안내판.
- 미션 탭 = "이 과제를 끝내면 도장(보상)을 받는" 과제 목록. 도장은 그 자리에서 받는다(헤더의 공용 상자로 가지 않음).
- 과목 정보 탭 = "이 요리(취약점)가 무엇이고, 잘못하면 어떻게 되고, 어떻게 안전하게 하는지" 설명서.

---

## 3. 용어 설명

| 용어 | 뜻 |
|---|---|
| 미션(task) | 과목의 학습 단계. 개념 학습 · 실습 성공 · 방어 퀴즈 3가지 |
| 보상(reward) | 미션 달성 시 지급되는 경험치 또는 포인트 |
| 미수령(pending) | 달성했지만 아직 받지 않은 보상 상태 |
| 수령(claim) | 보상을 실제로 받아 보유치(경험치·포인트)에 더하는 동작 |
| 안내 카드 | 실습·과목 정보 탭에서 항목별로 내용을 담는 네모 칸 |

## 4. 화면 & 동작

### 4-1. 실습 탭

```
실습
┌ 🎯 실습 목적 ─────────┐┌ ❓ 왜 배우나 ─────────┐
│ ...                  ││ ...                  │
└─────────────────────┘└─────────────────────┘
┌ 🪟 실습 화면 ───────────────────────────────┐
┌ 1. 진행 방법 ───────────────────────────────┐
│ 1) ... 2) ... 3) ...                        │
│ 💡 팁: 하 → 중 → 상 순서로 진행하세요        │
└────────────────────────────────────────────┘
[ 실습 시작 ]
```

### 4-2. 미션 탭 (변경 핵심)

```
미션
┌──────────────────────────────────┬─────────────┐
│ [1회차] 개념 학습        [완료]    │  ⊘ 보상 없음 │
│ ┌ 설명 네모칸 ────────────────┐   │             │
│ └────────────────────────────┘   │             │
├──────────────────────────────────┼─────────────┤
│ [2회차] 실습 성공       [미완료]   │  🎁 보상 받기 │
│ ┌ 설명 네모칸 ────────────────┐   │ 경험치 +N    │
│ │ 실습 하러 가기 →            │   │ 포인트 +N    │
│ └────────────────────────────┘   │ (클릭 수령)  │
└──────────────────────────────────┴─────────────┘
[ 방어 퀴즈 풀기 ]
```

- **뺀 것**: "내 제출물" 라벨과 내용, 제출 날짜(예: 2026. 10. 4.) 칩.
- **넣은 것**: 미션 설명을 네모 칸에 표시. 오른쪽에 보상 슬롯.
- 보상 슬롯 상태: 보상 없음(개념) / 미션 완료 시 지급(미리보기) / 보상 받기(클릭 수령) / 수령 완료.

### 4-3. 과목 정보 탭

```
과목 정보
┌ ℹ️ 어떤 취약점인가 ──────────────────────────┐
┌ 💬 쉽게 말하면 (비유) ───────────────────────┐
┌ ⚠️ 막지 못하면 ──────┐┌ 🛡️ 방어 방법 ───────┐
┌ 💻 공격 예시 (참고) ─────────────────────────┐
```

## 5. 동작 원리 (미션 보상)

```
[실습 성공 또는 퀴즈 통과]
      │  서버가 보상을 "미수령" 상태로 생성 (roll_pending)
      ▼
[미션 탭 열기]  GET /courses/<slug>/rewards
      - 미션별 상태 계산: none / locked / pending / claimed
      ▼
[오른쪽 "보상 받기" 클릭]  POST /courses/<slug>/rewards/<task>/claim
      - 본인·해당 미션의 미수령 보상만 잠금 조회
      - 원장(경험치·포인트)에 기록 → 보유치 증가
      ▼
[슬롯이 "수령 완료"로 변경, 상단 보유 포인트·레벨 즉시 갱신]
```

### 왜 이렇게 했나

- **보상을 맥락 안에서 수령**: 어떤 미션의 보상인지 바로 옆에서 보고 받으므로, 공용 보물상자보다 직관적이다.
- **금액은 서버만 신뢰**: 수령 요청에 금액을 받지 않고 DB에 저장된 값만 반영한다. 행을 잠그고(`FOR UPDATE`) 처리해 중복 수령을 막는다.
- **기존 멱등성 유지**: 보물상자 시절 생성된 미수령 보상과 그보다 전에 자동 지급된 기록 모두 올바른 상태(수령 대기/완료)로 표시된다.
- **"내 제출물" 제거**: 제출물·날짜는 학습자에게 큰 의미가 없고, 미션이 무엇인지 설명하는 것이 더 유용하다는 요청을 반영했다.
- **과목별 콘텐츠 분리**: 설명을 `courseGuides.js` 한 곳에 모아, 화면 코드와 내용을 분리하고 유지보수를 쉽게 했다.

## 6. 난이도(단계) 대신 — 탭별 역할

| 탭 | 답해 주는 질문 |
|---|---|
| 실습 | 무엇을, 왜, 어떻게 실습하나? |
| 미션 | 어떤 과제가 있고, 보상은 어떻게 받나? |
| 과목 정보 | 이 취약점은 무엇이고, 막지 못하면 어떻게 되며, 어떻게 방어하나? |

---

## 7. 핵심 정리

- 과목 상세의 세 탭을 입문자 기준으로 보완했다: 실습(목적·방법), 미션(설명+보상), 과목 정보(원리·영향·방어).
- 미션 탭에서 "내 제출물·날짜"를 빼고 **미션 설명 + 오른쪽 보상 수령**으로 바꿨다.
- 보상은 헤더 보물상자가 아니라 **해당 과목 미션 탭에서만** 받는다. 보물상자는 제거했다.
- 과목별 설명은 `courseGuides.js` 한 파일에 8개 과목 모두 정리했다.

---

## 8. 검증

- 백엔드 `courses.py` · `rewards.py` 문법 검사 통과
- 프런트 `CourseDetailView.vue` · `RewardSlot.vue` · `courseGuides.js` · 수정된 `AppHeader.vue` · `reward.js` Vite 모듈 로드 통과
- API(관리자 세션): 전역 수령 `/rewards/<id>/claim` → 404(제거 확인), 미수령 목록 `/rewards/pending`은 유지
- 헤더에서 보물상자 아이콘이 사라진 것 확인
- **학생 화면(실습/미션/과목 정보 탭 표시, 보상 받기 클릭)은 확인 필요** — 학생 계정 로그인이 필요하며, 이 세션에서는 학생 비밀번호를 알 수 없음
