# 02. 실습 보상 조건(하·중·상 모두 통과) · 미션 탭 보상 수령 정리

> 대상: 웹 보안을 처음 배우는 입문자
> 목표: 실습 보상이 언제 지급되는지, 미션 탭 오른쪽 보상 칸이 언제 "보상 받기"로 바뀌는지 이해한다.
> 작성: 2026-10-04 · 오현명

---

## 1. 요약

- **실습 보상 조건 변경**: 레벨 하나만 성공해도 주던 실습 보상을, 이제 **하 · 중 · 상 3개 레벨을 모두 통과해야** 지급한다. 지급된 보상은 그대로 **헤더 보물상자**에서 받는다.
- **실습 미션 완료 조건도 동일**: 미션 탭의 "2회차 실습 성공"도 하·중·상을 모두 통과해야 "완료"가 된다.
- **미션 탭 보상 칸**: 미션을 **실제로 완수한 경우에만** 오른쪽 칸에 받을 보상(종류·금액)이 표시되고, 클릭하면 바로 받는다.
- **누락 보상 보정**: 미션은 완료했는데 보상 기록이 없던 경우(보상 기능 도입 전에 완료한 개념 학습 등)도 미션 탭을 열면 "보상 받기"로 표시된다.

---

## 2. 개념 설명 (비유)

**3단 자격증 시험**과 같다.

- 1급·2급·3급(하·중·상)을 **모두 합격해야** 자격증 수당(실습 보상)이 나온다. 수당은 택배 보관함(보물상자)으로 온다.
- 교실 도장판(미션 탭)은 과제를 **정말로 끝낸 칸에만** 도장 받기 버튼이 생긴다. 끝내지 않은 칸은 "완료 시 지급" 안내만 보인다.

---

## 3. 용어 설명

| 용어 | 뜻 |
|---|---|
| `PRACTICE_REWARD_TIERS` | 실습 보상·실습 미션 완료에 필요한 레벨 목록 `("low", "medium", "high")` |
| 보정(backfill) | 완수했는데 빠져 있던 보상 기록을 나중에 채워 넣는 것 |
| 멱등 | 여러 번 실행해도 결과가 한 번 실행한 것과 같음 (보상이 두 번 생기지 않음) |

## 4. 화면 & 동작

### 4-1. 실습 페이지 결과 문구

| 상황 | 문구 |
|---|---|
| 하 또는 중만 통과 | "하·중·상 레벨을 모두 통과하면 실습 보상이 보물상자로 지급됩니다. (현재 N/3 통과)" |
| 상까지 통과(첫 지급) | "보상 대기 중: 경험치(포인트) +N — 헤더의 보물상자에서 받으세요" |
| 이미 보상을 받은 과목 | "이미 실습 보상을 받은 과목입니다." |

### 4-2. 미션 탭 오른쪽 보상 칸

| 미션 | 완수 조건 | 완수 전 | 완수 후 |
|---|---|---|---|
| 1회차 개념 학습 | 과목 정보 학습 완료 | 미션 완료 시 지급(범위) | **보상 받기** (클릭 수령) |
| 2회차 실습 성공 | 하·중·상 모두 통과 | 미션 완료 시 지급(범위) | 보물상자에서 받기(안내) → 수령 후 "수령 완료" |
| 3회차 방어 퀴즈 | 퀴즈 70% 이상 | 미션 완료 시 지급(범위) | **보상 받기** (클릭 수령) |

### 관련 파일

| 파일 | 역할 |
|---|---|
| `backend/app/courses.py` | 실습 실행 시 하·중·상 모두 통과해야 실습 미션 완료·보상 생성, 미션 탭 조회 시 누락 보상 보정(`_backfill_mission_rewards`) |
| `frontend/src/views/ChapterDetailView.vue` | 실습 결과에 보상 조건 진행(N/3) 안내 |
| `frontend/src/content/courseGuides.js` | 2회차 실습 성공 미션 설명 변경 |

## 5. 동작 원리

```
[실습 실행]  POST /courses/<slug>/practice/run
      - 성공 → 해당 레벨 통과 기록
      - 통과한 레벨에 low·medium·high 가 모두 있으면
          → 실습 미션 완료 + 실습 보상 생성(과목당 1회) → 보물상자
      - 아니면 보상 없이 "N/3 통과" 안내

[미션 탭 열기]  GET /courses/<slug>/rewards
      - 완료된 미션(개념 학습·방어 퀴즈) 중 보상 기록이 없으면 미수령 보상 생성(멱등)
      - 완료 안 된 미션은 생성하지 않음 → "미션 완료 시 지급"
      ▼
[보상 받기 클릭]  POST /courses/<slug>/rewards/<미션>/claim
      - 서버에 저장된 금액만 원장에 반영 → 보유 경험치·포인트 증가
```

### 왜 이렇게 했나

- **레벨 학습 동기 부여**: 하만 풀고 보상을 받으면 중·상을 건너뛸 이유가 생긴다. 3개 레벨을 모두 통과해야 보상을 줘 "하 → 중 → 상" 학습을 끝까지 이끈다.
- **미션 완료와 보상을 일치**: "완료"인데 보상 칸이 비어 있던 어긋남을 없앴다. 완료 여부는 서버의 진도 기록으로만 판단하므로 완수하지 않은 미션에는 보상이 생기지 않는다.
- **중복 지급 방지**: 보정은 기존 `roll_pending` 을 그대로 써서 같은 미션 보상이 두 번 생기지 않는다(이미 받은 원장 기록까지 확인).
- **기존 기록은 유지**: 변경 전에 이미 생성·수령된 실습 보상과 완료 기록은 그대로 두고, 새 규칙은 앞으로의 실습부터 적용된다.

---

## 6. 난이도(단계) 대신 — 실습 보상 진행 단계

| 통과 레벨 | 실습 미션 | 실습 보상 |
|---|---|---|
| 하 | 미완료 | 없음 (1/3) |
| 하 · 중 | 미완료 | 없음 (2/3) |
| 하 · 중 · 상 | **완료** | **보물상자로 지급** |
| + 안전 | 완료 | (추가 보상 없음, 방어 원리 확인) |

---

## 7. 핵심 정리

- 실습 보상은 **하·중·상을 모두 통과**해야 지급되고, 보물상자에서 받는다.
- 미션 탭은 **미션을 완수한 칸에만** 받을 보상이 표시되고, 클릭하면 받는다.
- 완료했는데 보상이 없던 미션도 미션 탭을 열면 받을 수 있게 보정된다.

---

## 8. 검증

- 백엔드 `courses.py` 문법 검사 통과
- `GET /courses/command-injection/rewards`: 완료된 개념 학습에 미수령 보상(경험치 +33) 생성 → `status: pending` 확인, 미완료인 방어 퀴즈는 `locked` 유지 확인
- 미션 탭 화면: 1회차 개념 학습 칸이 "받을 수 있어요! 보상 받기 · 경험치 +33" 으로 표시 확인
- **확인 필요**: 새 과목에서 하·중만 통과 시 보상 미지급(N/3 안내), 상 통과 시 보물상자 지급 — 실습으로 직접 확인 권장
