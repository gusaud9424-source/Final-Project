# 01. 보상 수령 위치 정리 (실습 보상 → 보물상자)

> 대상: 웹 보안을 처음 배우는 입문자
> 목표: 어떤 보상을 어디서 받는지(보물상자 / 미션 탭) 구분하고, 서버가 그 규칙을 어떻게 지키는지 이해한다.
> 작성: 2026-10-04 · 오현명

---

## 1. 요약

- **변경 전**: 실습 성공 보상이 **미션 탭에서만** 수령 가능했다. 실습 페이지에서 성공해도 헤더 보물상자에는 아무것도 뜨지 않았다.
- **변경 후 규칙**
  - **보물상자(헤더 🎁)**: 실습 페이지 실습 성공, 출석 체크 등 **미션 외 모든 보상**
  - **미션 탭**: 개념 학습 · 방어 퀴즈(미션) 보상만
- 미션 탭의 "실습 성공" 칸은 버튼 대신 **"보물상자에서 받기"** 안내만 보여준다.
- 지급 기준은 그대로다: 실습 보상은 **과목당 1회**(처음 실습에 성공했을 때), 금액은 서버에서 정한다.
- 이전에 미션 탭에서 받지 않고 쌓여 있던 실습 보상도 모두 보물상자에 나타난다.

---

## 2. 개념 설명 (비유)

**택배 보관함과 수업 도장판**으로 나눈 것과 같다.

- 보물상자 = 아파트 **택배 보관함**. 실습 성공, 출석 같은 보상은 어디서 생겼든 전부 여기로 모인다.
- 미션 탭 = 교실의 **도장판**. 개념 학습·퀴즈 미션 도장은 그 과목 교실에서만 찍어 준다.
- 도장판에는 "택배는 보관함에 도착했어요" 메모(보물상자에서 받기)만 붙여, 같은 보상을 두 곳에서 받는 일이 없게 했다.

---

## 3. 용어 설명

| 용어 | 뜻 |
|---|---|
| source | 보상이 생긴 이유. `practice`(실습) · `concept`(개념 학습) · `mission`(방어 퀴즈) · 출석 등 |
| 미수령(pending) | 생성됐지만 아직 받지 않은 보상 |
| `COURSE_REWARD_SOURCES` | 미션 탭에서만 받는 보상 종류 목록. 이번에 `("concept", "mission")` 으로 변경 |
| `claimAt` | 미션 탭 보상 상태에 추가한 값. `mission`(여기서 수령) / `chest`(보물상자에서 수령) |

---

## 4. 화면 & 동작

### 4-1. 보상별 수령 위치

| 보상 | 생기는 시점 | 받는 곳 |
|---|---|---|
| 실습 성공 | 실습 페이지에서 처음 성공 (과목당 1회) | **보물상자** |
| 출석 체크 등 | 해당 기능 사용 시 | **보물상자** |
| 개념 학습 | 과목 정보 학습 완료 | 미션 탭 |
| 방어 퀴즈(미션) | 퀴즈 70% 이상 통과 | 미션 탭 |

### 4-2. 미션 탭 화면

```
미션
개념 학습·퀴즈 미션 보상은 오른쪽에서 받습니다. 실습 성공 보상은 헤더의 보물상자에서 받으세요.
┌ [1회차] 개념 학습 ───────────────┬──────────────┐
│ ...                             │ 🎁 보상 받기   │ ← 미션 탭에서 수령
├ [2회차] 실습 성공 ───────────────┼──────────────┤
│ ...                             │ 🎁 보물상자에서 받기 │ ← 안내만 (클릭 없음)
│                                 │ 경험치 +57    │
├ [3회차] 방어 퀴즈 통과 ──────────┼──────────────┤
│ ...                             │ 🎁 보상 받기   │ ← 미션 탭에서 수령
└─────────────────────────────────┴──────────────┘
```

### 4-3. 실습 페이지 결과 문구

- 변경 전: "보상 대기 중: 경험치 +N — 과목 상세의 미션 탭에서 받으세요"
- 변경 후: "보상 대기 중: 경험치 +N — **헤더의 보물상자에서 받으세요**"

### 관련 파일

| 파일 | 역할 |
|---|---|
| `backend/app/rewards.py` | `COURSE_REWARD_SOURCES` 에서 `practice` 제외 → 보물상자 목록·수령·일괄 수령에 실습 보상 포함 |
| `backend/app/courses.py` | 미션 탭 보상 상태에 `claimAt` 추가, 미션 탭에서 실습 보상 수령 요청 시 400 거부 |
| `frontend/src/components/practice/RewardSlot.vue` | `claimAt: chest` 이면 "보물상자에서 받기" 안내 표시 |
| `frontend/src/views/CourseDetailView.vue` | 미션 탭 안내 문구 변경, 수령 가능 개수에서 보물상자 대상 제외 |
| `frontend/src/views/ChapterDetailView.vue` | 실습 결과의 수령 위치 안내 문구 변경 |

## 5. 동작 원리

```
[실습 페이지에서 처음 성공]
      │  roll_pending(source="practice") → 미수령 보상 생성 (과목당 1회, 멱등)
      ▼
[헤더 보물상자]  GET /rewards/pending
      - source 가 COURSE_REWARD_SOURCES(개념·미션)가 아닌 미수령 보상만 조회
      - 실습 보상이 목록에 포함됨 → 배지 숫자 증가
      ▼
[클릭 수령]  POST /rewards/<id>/claim  또는  /rewards/claim-all
      - 서버가 source 재확인 → 원장(경험치·포인트)에 기록

[미션 탭]  GET /courses/<slug>/rewards
      - practice 항목은 claimAt="chest" → "보물상자에서 받기" 안내만 표시
      - 미션 탭 수령 API로 실습 보상을 요청하면 400 ("보물상자에서 받으세요")
```

### 왜 이렇게 했나

- **한 보상은 한 곳에서만**: 수령 위치가 둘이면 중복 수령 위험과 혼란이 생긴다. 서버가 source 기준으로 받을 수 있는 곳을 하나로 정한다.
- **규칙을 한 상수로 관리**: `COURSE_REWARD_SOURCES` 하나만 바꾸면 보물상자 목록·개별 수령·일괄 수령·미션 탭 거부가 함께 바뀐다.
- **미션 탭에도 상태는 남김**: 미션 "실습 성공"을 달성했는지, 보상이 얼마인지는 그대로 보여주고 받는 곳만 안내한다.
- **지급 기준은 유지**: 레벨(하·중·상) 구조와 별개로 실습 보상은 과목당 1회다. 레벨마다 지급하려면 별도 변경이 필요하다.

---

## 6. 난이도(단계) 대신 — 미션 탭 보상 칸 상태

| 상태 | 표시 | 클릭 |
|---|---|---|
| 미달성 | 미션 완료 시 지급 (범위 미리보기) | 불가 |
| 수령 대기 (개념·미션) | 받을 수 있어요! 보상 받기 | 가능 |
| 수령 대기 (실습) | 보물상자에서 받기 | 불가 (보물상자 이용) |
| 수령 완료 | 수령 완료 | 불가 |

---

## 7. 핵심 정리

- 실습 성공·출석 등 **미션 외 보상은 전부 보물상자**, **개념 학습·방어 퀴즈 보상만 미션 탭**에서 받는다.
- 미션 탭의 실습 칸은 "보물상자에서 받기" 안내로 바뀌었고, 서버도 미션 탭에서의 실습 보상 수령을 거부한다.
- 실습 보상은 지금처럼 과목당 1회 지급된다.

---

## 8. 검증

- 백엔드 `rewards.py` · `courses.py` 문법 검사 통과
- `GET /rewards/pending`: 기존에 쌓여 있던 실습 보상 6건(Command Injection 경험치 +57 등)이 보물상자 목록에 표시, 헤더 배지 6 확인
- `GET /courses/command-injection/rewards`: practice 항목 `claimAt: "chest"` 확인
- 미션 탭 화면: 실습 성공 칸이 "보물상자에서 받기 · 경험치 +57" 로 표시 확인
- **확인 필요**: 보물상자에서 실제 수령 클릭 후 보유 경험치·포인트 증가 (사용자 계정에서 직접 확인 권장)
