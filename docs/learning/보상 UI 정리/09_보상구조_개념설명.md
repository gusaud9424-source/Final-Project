## 1. 요약

- 보상은 **경험치(XP)** 와 **포인트(P)** 두 종류다. 경험치가 쌓이면 레벨이 오른다.
- 보상은 바로 지급되지 않고, 먼저 **"받을 수 있는 보상(미수령)"** 으로 만들어진 뒤 학생이 **클릭해서 받는다(수령)**.
- 받는 곳은 두 군데다.
  - **미션 탭 오른쪽 칸**: 과목의 1~3회차 미션 보상 (개념 학습 · 실습 성공 · 방어 퀴즈)
  - **헤더 보물상자 🎁**: 실습 레벨 클리어 · 레벨업 보상
  - (예외) **출석 포인트**는 출석 체크판에서 버튼을 누르는 순간 바로 적립된다(교환권 없이 원장에 직접 기록). → `출석 체크와 포인트 지급/02` 참고
- 같은 보상은 **한 번만** 받는다. 서버가 "이 보상 이미 만들었나/받았나"를 확인하고, 동시에 두 번 눌러도 한 번만 처리되게 잠근다.
- 미션은 **조건을 실제로 채워야** 완료된다. 예전 기록이 남아 있어도 지금 규칙에 맞지 않으면 완료로 보지 않는다.
- 수강신청하면 그 과목 진도는 **0%에서 다시 시작**한다. 단, 이미 받은 보상은 다시 주지 않는다.

## 2. 개념 설명 (비유)

### 2-1. 전체 그림: 은행 통장과 교환권

```
 [학생 행동]                 [교환권 발급]               [교환]                 [통장]
 실습 클리어 ──┐
 퀴즈 통과 ────┼──▶  Reward(교환권) 생성  ──▶  클릭해서 받기  ──▶  원장(통장)에 입금
 레벨업 ───────┘     "미수령" 상태             (미션 탭/보물상자)    xp_ledger / point_ledger
                                                                       │
                                                                       ▼
                                                            합계 → 레벨 · 보유 포인트
```

- **교환권(Reward)**: "경험치 57을 받을 수 있음"이라고 적힌 표. 아직 통장에 들어가지 않았다.
- **교환(수령)**: 학생이 클릭하면 교환권에 "사용함" 도장을 찍고 통장에 입금한다.
- **통장(원장, ledger)**: 실제로 받은 경험치·포인트가 한 줄씩 기록되는 장부. 합계가 곧 내 경험치·포인트다.

### 2-2. 왜 바로 주지 않고 "교환권"을 만드나

- 학생이 **보상을 직접 확인하고 받는 재미**를 주기 위해서다(보물상자 열기).
- 금액이 **서버에서 한 번 정해지면 바뀌지 않게** 하기 위해서다. 교환권에 금액이 이미 적혀 있으므로, 받을 때 화면이 금액을 바꿔 보내도 소용없다.
- 어떤 보상을 받았고 안 받았는지 **기록이 남아** 관리자 화면에서 확인할 수 있다.

## 3. 용어 설명

| 용어 | 쉬운 뜻 |
|---|---|
| 경험치(XP) | 학습할수록 쌓이는 점수. 쌓이면 레벨이 오른다 |
| 포인트(P) | 모아서 쓰는 점수(보유 포인트) |
| Reward(보상 행) | 교환권. `rewards` 테이블의 한 줄 |
| 미수령(pending) | 교환권이 만들어졌지만 아직 받지 않은 상태 (`claimed_at` 이 비어 있음) |
| 수령(claim) | 교환권을 사용해 통장에 넣는 동작 |
| 원장(ledger) | 실제 받은 기록 장부. `xp_ledger`, `point_ledger` 테이블 |
| source | 보상이 생긴 이유 (예: `concept`, `practice`, `mission`, `practice_low`, `levelup`, `attendance`) |
| ref | 중복 방지용 이름표 (예: `mission:xss-dom`, `practice:csrf:high`, `levelup:3`) |
| 멱등(idempotent) | 같은 일을 여러 번 해도 결과가 한 번 한 것과 같음. "이미 있으면 또 만들지 않음" |
| 트랜잭션 | 여러 DB 작업을 "전부 성공 아니면 전부 취소"로 묶은 단위 |
| 행 잠금(FOR UPDATE) | DB의 특정 줄을 잠시 잠가, 다른 요청이 동시에 같은 줄을 바꾸지 못하게 하는 것 |
| UNIQUE 제약 | DB에 "같은 값 조합은 한 줄만 허용"하는 규칙 |
| task_progress | 미션 완료 기록 테이블. 레벨 통과·확인 문제 통과 표시도 함께 저장 |

## 4. 구조와 코드

### 4-1. 보상은 언제 생기나 (교환권 발급)

| 보상 | 생기는 조건 | source / ref | 받는 곳 | 금액 범위 |
|---|---|---|---|---|
| 1회차 개념 학습 | 확인 문제 5개 중 3개 이상 정답 | `concept` / `concept:<과목>` | 미션 탭 | XP 20~50 또는 P 10~20 |
| 2회차 실습 성공 | 하·중·상 레벨 모두 통과 | `practice` / `practice:<과목>` | 미션 탭 | XP 50~100 또는 P 20~40 |
| 3회차 방어 퀴즈 | 퀴즈 70% 이상 | `mission` / `mission:<과목>` | 미션 탭 | XP 30~80 또는 P 10~30 |
| 실습 레벨 클리어 | 하·중·상·안전 각 레벨 첫 통과 | `practice_<레벨>` / `practice:<과목>:<레벨>` | 보물상자 | 하 XP 20~40 · 중 40~70 · 상 70~110 · 안전 20~40 |
| 레벨업 | 레벨이 오를 때마다 (2레벨부터) | `levelup` / `levelup:<레벨>` | 보물상자 | 종류 랜덤, 레벨이 높을수록 증가 |
| 출석 | 출석 체크판에서 하루 1회 버튼 클릭 | `attendance` / `att:<날짜>` | **출석판에서 즉시 적립** (교환권 없음) | P 50~200, 7·14일차 300~500 |

- 과목 미션·레벨 보상의 종류는 **과목별로 고정**이다. 초급 과목은 경험치, 중급·고급 과목은 포인트로 준다.
- 레벨업 보상만 경험치/포인트 중 **랜덤**이다.

### 4-2. 교환권 만들기: `roll_pending` (멱등 + 잠금)

```python
# backend/app/rewards.py (요약)
def roll_pending(user_id, source, reason, ref, course_slug=None):
    types = _reward_types(source, course_slug)          # ① 이 과목은 경험치? 포인트?
    db.session.query(User).filter_by(id=user_id).with_for_update().one()   # ② 사용자 행 잠금
    if _already_rewarded(user_id, source, ref):         # ③ 같은 ref 교환권/입금 기록이 있으면
        db.session.rollback()
        return []                                       #    아무것도 만들지 않음 (멱등)
    rows = [Reward(user_id=user_id, type=t,
                   amount=random.randint(*RANGES[t][source]),   # ④ 금액은 서버가 결정
                   source=source, ref=ref, reason=reason) for t in types]
    db.session.add_all(rows)
    db.session.commit()                                 # ⑤ 저장 (UNIQUE 위반 시 이미 있는 것으로 처리)
    return rows
```

| 줄 | 의미 | 없으면 생기는 일 |
|---|---|---|
| ② 행 잠금 | 같은 학생의 요청이 동시에 두 개 와도 하나씩 차례로 처리 | 버튼을 빠르게 두 번 누르면 교환권이 두 장 생길 수 있음 |
| ③ 중복 확인 | 교환권(`rewards`)과 통장(`ledger`) 모두에서 같은 ref 를 찾음 | 같은 미션 보상을 여러 번 받을 수 있음 |
| ④ 서버가 금액 결정 | 금액 범위는 서버 코드에만 있음 | 화면(브라우저)이 금액을 조작해 보낼 수 있음 |
| ⑤ UNIQUE 제약 | DB 차원에서 `(user, source, ref, type)` 중복 금지 | 잠금이 실패한 극단적 경우에도 중복 저장 가능 |

### 4-3. 교환하기(수령): `_apply_claim`

```python
def _apply_claim(reward):
    reward.claimed_at = datetime.utcnow()                    # 교환권에 "사용함" 도장
    ledger_model = LEDGER_MODELS[reward.type]                # 경험치 장부 or 포인트 장부
    db.session.add(ledger_model(user_id=reward.user_id, source=reward.source,
                                ref=reward.ref, amount=reward.amount, reason=reward.reason))
```

- 수령 API는 **본인 · 미수령 · 받을 수 있는 곳**인지 확인한 뒤 이 함수를 부른다.
- 금액은 요청에서 받지 않고 **교환권에 적힌 값만** 쓴다.

### 4-4. 어디서 받나: `COURSE_REWARD_SOURCES`

```python
# 과목 미션 탭에서만 받는 보상 (1~3회차, 각 1개)
COURSE_REWARD_SOURCES = ("concept", "practice", "mission")
```

| 요청 | 확인 내용 | 결과 |
|---|---|---|
| 보물상자 목록 `GET /rewards/pending` | source 가 위 목록에 **없는** 미수령만 | 레벨 클리어·레벨업 보상 표시 |
| 보물상자 수령 `POST /rewards/<id>/claim` | 위 목록에 있으면 거부(400) | 미션 보상은 보물상자에서 못 받음 |
| 미션 탭 수령 `POST /courses/<과목>/rewards/<미션>/claim` | 위 목록에 있고 **미션을 완수**했는지 | 미완수면 403 |

> 이렇게 "받는 곳"을 서버가 정해 두면, 같은 보상을 두 곳에서 받는 일이 원천적으로 없다.

### 4-5. 미션 완료 판정: `effective_task_rows`

```python
# backend/app/progress.py (요약)
for row in rows:                       # 같은 학생·과목의 task_progress 기록들
    if row.task_key == "practice" and not {"tier_low", "tier_medium", "tier_high"} <= marks:
        continue                       # 하·중·상 통과 표시가 다 없으면 실습 미션 미완료
    if row.task_key == "concept" and "concept_check" not in marks:
        continue                       # 확인 문제 통과 표시가 없으면 개념 학습 미완료
    result.append(row)
```

- 왜 필요했나: 규칙이 바뀌기 전("레벨 하나만 성공해도 완료", "탭만 열어도 완료")에 생긴 기록이 남아 있었다. 기록을 지우지 않고 **판정만 새 규칙으로** 바꿨다.
- 이 함수를 **진도율 · 미션 탭 · 관리자 화면 · 수령 API** 가 모두 같이 쓴다. 판정 기준이 한 곳이라 화면마다 결과가 달라지지 않는다.

### 4-6. 레벨과 레벨업 보상

```python
def compute_level(total_xp):          # 누적 경험치 → 레벨
    level, remaining = 1, total_xp
    while level < 50:
        needed = level * 100          # 1→2: 100, 2→3: 200, 3→4: 300 ...
        if remaining < needed: break
        remaining -= needed; level += 1
```

| 레벨 | 다음 레벨까지 필요 경험치 | 누적 경험치 |
|---|---|---|
| 1 → 2 | 100 | 100 |
| 2 → 3 | 200 | 300 |
| 3 → 4 | 300 | 600 |

```python
def levelup_range(reward_type, level):            # 레벨업 보상 금액
    if reward_type == "xp":
        return (20 + level * 15, 40 + level * 20) # 2레벨 50~80, 10레벨 170~240
    return (10 + level * 5, 20 + level * 8)       # 2레벨 20~36, 10레벨 60~100
```

- `ensure_levelup_rewards` 가 **2레벨부터 현재 레벨까지** 중 아직 없는 `levelup:<레벨>` 교환권만 만든다.
- 언제 확인하나: 보물상자 목록을 열 때, 보상을 받은 직후.
- 레벨업 보상으로 받은 경험치 때문에 또 레벨이 오르면, 다음 확인 때 그 레벨 교환권도 생긴다.

### 4-7. 수강신청하면 0%부터

```python
# backend/app/enrollments.py
def _reset_course_progress(user_id, course):
    TaskProgress.query.filter_by(user_id=user_id, course_id=course.id).delete()   # 미션·레벨·확인문제 기록
    Reward.query.filter(Reward.user_id == user_id, Reward.claimed_at.is_(None),
                        <이 과목 ref>).delete()                                    # 받지 않은 과목 교환권
```

| 데이터 | 수강신청 시 | 이유 |
|---|---|---|
| 미션·레벨·확인문제 기록 | 삭제 | 새로 시작 (진도 0%) |
| 받지 않은 과목 교환권 | 삭제 | 새 수강에서 다시 조건을 채워야 함 |
| 이미 받은 기록(통장) | **유지** | 취소·재신청을 반복해 같은 보상을 또 받는 것 방지 |

## 5. 동작 흐름 예시 (XSS DOM 과목, 처음부터)

```
1. 수강신청 → 진도 0%, 미션 탭 1~3회차 모두 "미션 완료 시 지급"
2. 과목 정보 탭 → 확인 문제 4/5 정답 → 1회차 완료 → 미션 탭 1회차 "보상 받기" → 클릭 → 경험치 입금
3. 실습: 하 통과 → 보물상자 "하 레벨" 교환권 → 중 통과 → "중 레벨" → 상 통과 → "상 레벨"
        + 하·중·상 모두 통과 → 2회차 완료 → 미션 탭 2회차 "보상 받기"
4. 방어 퀴즈 70% 이상 → 3회차 완료 → 미션 탭 3회차 "보상 받기"
5. 받은 경험치로 레벨 2 달성 → 보물상자 "레벨 2 달성" 교환권 (경험치 또는 포인트)
```

## 6. 주의점과 한계

- **확인 문제 문항이 아직 비어 있다.** `backend/app/concept_check.py` 에 과목별 5문항 이상을 넣기 전까지 1회차는 "준비 중"이라 완료할 수 없다.
- **예전 기록은 남아 있다.** 판정 함수가 무시할 뿐 지우지 않았다. 확인이 필요하면 `docker compose exec backend flask show-progress --email <이메일> --course <과목>` 으로 본다.
- **레벨 클리어 보상과 2회차 미션 보상은 별개다.** 하·중·상을 통과하면 레벨 보상 3개(보물상자) + 2회차 보상 1개(미션 탭)를 받는다.

## 7. 핵심 정리

- 보상은 **교환권(Reward) → 클릭 수령 → 통장(ledger) 입금** 순서로 지급된다. 금액은 서버가 교환권을 만들 때 정한다.
- **미션 1~3회차는 미션 탭**, **레벨 클리어·레벨업은 보물상자**에서 받는다. 서버가 받는 곳을 강제한다. 출석 포인트는 출석판에서 바로 적립된다.
- **ref 이름표 + 행 잠금 + UNIQUE 제약**으로 같은 보상은 한 번만 생기고 한 번만 받는다.
- 미션 완료는 `effective_task_rows` 한 곳에서 판정해, 예전 기록이 있어도 **지금 규칙을 채워야** 완료된다.
- 수강신청하면 진도는 0%부터, 이미 받은 보상은 다시 주지 않는다.
- 발표용 한 문장: **"보상은 서버가 금액을 정한 교환권으로 만들어 학생이 직접 받게 하고, 이름표와 잠금으로 중복 지급을 막으며, 미션은 실제 조건을 채워야만 완료된다."**
