# 06. 미션 완수 조건 보정 (이전 규칙 기록 정리)

> 대상: 웹 보안을 처음 배우는 입문자
> 목표: 규칙이 바뀐 뒤 예전 기록 때문에 생긴 "하지 않은 미션의 보상 받기" 문제를 어떻게 고쳤는지 이해한다.
> 작성: 2026-10-05 · 오현명
> 📘 개념 설명(용어·코드 의미·최종 구조)은 `09_보상구조_개념설명.md` 참고.

---

## 1. 요약

- **문제**: XSS (DOM) 미션 탭에서 2회차를 진행하지 않았는데 "보상 받기(경험치 +91)"가 표시됐다.
- **원인**: 10월 2일 "아무 레벨 1회 성공 = 실습 완료" 규칙일 때 생긴 완료 기록과 보상이 남아 있었다. 2회차 보상을 미션 탭 수령으로 되돌리면서 그 보상이 드러났다.
- **조치**: 2회차 "실습 성공"은 저장된 완료 기록과 상관없이 **하·중·상 레벨 통과 기록이 모두 있어야 완료**로 본다. 진도율·관리자 화면·미션 탭 모두 같은 기준을 쓴다.
- 미션 탭은 **완수한 미션만** 보상을 받을 수 있다. 서버도 완수하지 않은 미션의 수령 요청을 403으로 거부한다.
- 3회차(방어 퀴즈)는 기록 확인 결과 10월 3일에 실제 통과한 것이었다. 정상이다.
- 예전 기록은 지우지 않았다. 조건을 채우면 그대로 완료·보상 수령이 된다.

---

## 2. 개념 설명 (비유)

**바뀐 졸업 요건**과 같다.

- 예전에는 과제 1개만 내도 "이수"였는데, 이제는 3개(하·중·상)를 모두 내야 이수다.
- 예전 기준으로 찍힌 "이수" 도장은 지우지 않지만, 성적표는 새 기준으로 다시 계산해서 보여준다.

## 3. 용어 설명

| 용어 | 뜻 |
|---|---|
| `effective_task_rows` | task_progress 기록 중 현재 규칙으로 유효한 미션 완료만 골라내는 함수 |
| `tier_low` 등 | 레벨 통과 기록 (하·중·상·안전) |
| `show-progress` | 사용자·과목의 완료·보상 기록을 보여주는 읽기 전용 점검 명령 |

## 4. 화면 & 동작

### 4-1. 점검 결과 (demo1 / xss-dom)

| 기록 | 시각 | 판단 |
|---|---|---|
| practice 완료 | 2026-10-02 21:12 | 이전 규칙(1회 성공) 기록 — 레벨 통과 기록 없음 → **미완료로 표시** |
| practice 보상 xp 91 | 생성 10-02, 미수령 | 미션 완수 전까지 받을 수 없음 |
| defense 완료 | 2026-10-03 04:31 | 실제 퀴즈 통과 → 정상 |
| mission 보상 xp 76 | 수령 10-05 11:41 | 정상 |

### 4-2. 수정 후 미션 탭 (XSS DOM)

```
[2회차] 실습 성공   [미완료]   🎁 미션 완료 시 지급
[3회차] 방어 퀴즈   [완료]     ✅ 수령 완료 · 경험치 +76
```

### 점검 명령

```
docker compose exec backend flask show-progress --email <이메일> --course <과목 slug>
```

### 관련 파일

| 파일 | 역할 |
|---|---|
| `backend/app/progress.py` | `effective_task_rows`, `PROGRESS_QUERY_KEYS` 추가, `completed_tasks` 에 실습 레벨 조건 적용 |
| `backend/app/courses.py` | 미션 탭 보상 상태에 완수 여부 반영, 미완수 미션 수령 403 |
| `backend/app/dashboard.py` | 진도율 계산에 같은 기준 적용 |
| `backend/app/admin.py` | 관리자 전체·개인 현황에 같은 기준 적용 |
| `backend/app/cli.py` | `show-progress` 점검 명령 추가 |

## 5. 동작 원리

```
task_progress 조회 (미션 키 + tier_* 키 함께)
      ▼
effective_task_rows
      - concept / defense : 기록 있으면 완료
      - practice          : 기록 + tier_low·tier_medium·tier_high 모두 있어야 완료
      ▼
진도율 · 미션 탭 · 관리자 화면 · 보상 수령 판정에 공통 사용
```

### 왜 이렇게 했나

- **한 기준으로 통일**: 화면마다 완료 판정이 다르면 다시 어긋난다. 판정 함수 하나를 모든 곳에서 쓴다.
- **기록은 보존**: 예전 기록을 지우면 되돌릴 수 없다. 판정만 새 규칙으로 바꿔 데이터 손실 없이 정리했다.
- **서버에서 강제**: 화면 표시뿐 아니라 수령 API도 완수 여부를 확인해, 요청을 직접 보내도 받을 수 없다.

---

## 6. 난이도(단계) 대신 — 미션별 완수 판정

| 미션 | 완수 조건 |
|---|---|
| 1회차 개념 학습 | 개념 학습 완료 기록 |
| 2회차 실습 성공 | 하·중·상 레벨 통과 기록 모두 |
| 3회차 방어 퀴즈 | 퀴즈 70% 이상 통과 기록 |

---

## 7. 핵심 정리

- 예전 규칙으로 남은 2회차 완료 기록 때문에 보상이 잘못 표시됐고, 2회차는 이제 하·중·상 통과로만 완료된다.
- 모든 화면과 수령 API가 같은 완수 기준을 쓰며, 예전 기록은 지우지 않았다.
