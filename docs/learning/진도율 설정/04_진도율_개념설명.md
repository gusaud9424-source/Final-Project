# 04. 진도율 개념 설명 (학습 진도 · 전체 학생 현황 · 학생 개인 현황)

> 대상: 웹 보안을 처음 배우는 입문자
> 목표: 진도율이 어떤 기록으로, 어떤 계산으로 만들어지고, 학생 화면과 관리자 화면에서 숫자가 왜 항상 같은지를 코드와 함께 이해한다.

## 1. 요약

- 과목 하나는 **미션 3단계**로 이루어진다: **개념 학습(concept) · 실습 성공(practice) · 방어 퀴즈(defense)**.
- **과목 진도율 = 완료한 단계 수 ÷ 3 × 100** (반올림). 0% · 33% · 67% · 100% 네 가지 값이 나온다.
- 완료 기록은 `task_progress` 테이블에 쌓이고, **진도율은 저장하지 않고 볼 때마다 계산**한다.
- 같은 계산 규칙을 **학생 대시보드 · 학습 진도 화면 · 관리자 전체 현황 · 학생 개인 현황**이 모두 사용해서 숫자가 어긋나지 않는다.
- 단계 완료 판정은 지금 규칙을 따른다: 개념 학습은 **확인 문제 통과**, 실습 성공은 **하·중·상 레벨 모두 통과**가 있어야 완료로 센다.
- 관리자 화면은 학생마다 **진행중 / 정체 / 완료 / 미시작** 상태를 붙인다. 7일 넘게 활동이 없으면 "정체"다.

## 2. 개념 설명 (비유)

### 2-1. 전체 그림: 체크리스트와 계산기

```
 [학생 행동]                  [기록]                          [계산]                  [화면]
 확인 문제 통과 ──┐
 하·중·상 통과 ───┼──▶ task_progress 에 한 줄씩 기록 ──▶ effective_task_rows ──▶ progress_summary ──▶ 학생 대시보드
 퀴즈 70% 통과 ───┘     (concept / practice / defense)    (지금 규칙에 맞는     (완료 수 ÷ 3)        학습 진도
                        + 레벨·확인문제 표시               기록만 고름)                               관리자 전체 현황
                                                                                                   학생 개인 현황
```

- **체크리스트(task_progress)**: 과목마다 칸 3개. 끝낸 칸에 체크 기록이 한 줄 생긴다.
- **검사관(effective_task_rows)**: 체크가 진짜인지 확인한다. 예전 규칙으로 찍힌 체크(탭만 열어서 생긴 개념 학습 등)는 세지 않는다.
- **계산기(progress_summary)**: 진짜 체크 수를 세서 퍼센트로 바꾼다.

### 2-2. 왜 진도율을 저장하지 않고 매번 계산하나

- 진도율을 숫자로 저장해 두면, 기록이 바뀔 때마다 그 숫자도 같이 고쳐야 한다. 하나라도 빠뜨리면 **화면마다 숫자가 달라진다.**
- 체크 기록만 저장하고 볼 때마다 세면, **원본이 하나**라서 어느 화면이든 같은 결과가 나온다.
- 비유: 통장 잔액을 따로 적어 두지 않고, 입출금 내역을 매번 더해서 잔액을 보는 방식이다.

## 3. 용어 설명

| 용어 | 쉬운 뜻 |
|---|---|
| 진도율 | 과목 3단계 중 끝낸 비율(%) |
| 단계(task) | 과목 안의 미션. `concept`(개념 학습) · `practice`(실습 성공) · `defense`(방어 퀴즈) |
| TASK_KEYS | 단계 이름 목록 `("concept", "practice", "defense")` |
| task_progress | 단계 완료 기록 테이블. 사용자·과목·단계 이름·완료 시각을 저장 |
| effective_task_rows | 기록 중 지금 규칙으로 유효한 완료만 골라내는 함수 |
| progress_summary | 완료 수 · 전체 수(3) · 퍼센트를 계산하는 함수 |
| doneKeys | 화면에 보내는 "완료한 단계 이름 목록" (예: `["concept", "practice"]`) → 카드의 ✔ 표시 |
| 전체 진도율 | 수강 중인 모든 과목의 완료 단계 합 ÷ (수강 과목 수 × 3) |
| 평균 진도율 | (관리자) 수강 과목이 있는 학생들의 전체 진도율 평균 |
| 마지막 활동 | 단계 완료 시각과 포인트 적립 시각(출석 포함) 중 가장 최근 시각 |
| 정체 | 수강 중이고 미완료인데 마지막 활동(없으면 수강 시작일)이 7일보다 오래된 상태 |
| 집계 | 여러 기록을 모아 합계·평균·개수를 내는 것 |
| GROUP BY | DB에서 "사용자별로 묶어서 합계 내기" 같은 묶음 계산 |
| API | 화면이 서버에 데이터를 요청하는 주소 (예: `GET /api/v1/dashboard`) |
| role(역할) | 계정 종류. `student`(학생) / `admin`(관리자) |
| 403 | 권한이 없어 거절한다는 응답 번호 (학생이 관리자 API 를 부르면 403) |
| SVG / 도넛 차트 | 코드로 그리는 그림 / 가운데가 빈 원형 그래프 |
| CSV | 쉼표로 구분한 표 파일. 엑셀에서 열 수 있다 |

## 4. 구조와 코드

### 4-1. 진도율 계산

```python
# backend/app/progress.py
TASK_KEYS = ("concept", "practice", "defense")
TASK_TOTAL = len(TASK_KEYS)                    # 3

def progress_summary(done):
    completed = sum(1 for key in TASK_KEYS if key in done)
    return {
        "completed": completed,                # 완료 단계 수
        "total": TASK_TOTAL,                   # 3
        "percent": round(completed / TASK_TOTAL * 100),   # 0 / 33 / 67 / 100
    }
```

| 완료 단계 | 계산 | 진도율 |
|---|---|---|
| 0 | 0 ÷ 3 × 100 | 0% |
| 1 | 1 ÷ 3 × 100 = 33.3 | 33% |
| 2 | 2 ÷ 3 × 100 = 66.7 | 67% |
| 3 | 3 ÷ 3 × 100 | 100% |

### 4-2. 유효한 완료만 세기

```python
# backend/app/progress.py (요약)
def effective_task_rows(rows):
    for row in rows:
        if row.task_key not in TASK_KEYS: continue                       # 레벨·확인문제 표시는 진도에 안 셈
        if row.task_key == "practice" and not 하·중·상_통과표시_모두: continue
        if row.task_key == "concept" and not 확인문제_통과표시: continue
        result.append(row)
```

| 규칙 | 없으면 생기는 일 |
|---|---|
| 레벨·확인문제 표시는 진도에서 제외 | `tier_low` 같은 기록까지 세어 진도율이 100%를 넘을 수 있음 |
| 실습 성공 = 하·중·상 모두 통과 | 레벨 하나만 통과해도 33%가 올라감 (예전 규칙) |
| 개념 학습 = 확인 문제 통과 | 과목 정보 탭만 열어도 33%가 올라감 (예전 규칙) |

> 이 함수를 학생 대시보드(`dashboard.py`), 관리자 전체·개인 현황(`admin.py`), 과목 상세·미션 탭(`courses.py`)이 **모두 같이** 쓴다. 판정 기준이 한 곳이라 화면마다 결과가 같다.

### 4-3. 화면별 데이터 흐름

| 화면 | 요청 API | 서버가 주는 것 | 화면이 하는 일 |
|---|---|---|---|
| 학생 대시보드 · 학습 진도 | `GET /api/v1/dashboard` | 수강 과목별 completed · total · percent · doneKeys | 8개 과목 목록(enroll 스토어)에 진도를 붙여 카드로 표시, 난이도순(초급→중급→고급) 정렬 |
| 관리자 전체 학생 현황 | `GET /api/v1/admin/progress` | 요약 · 과목별 · 단계별 · 학생별 진도와 상태 | 카드·막대·표, 검색·필터·정렬·CSV 는 브라우저에서 처리 |
| 학생 개인 현황 | `GET /api/v1/admin/students/<id>` | 과목별 진도, 단계 완료 날짜, 레벨·포인트, 출석판, 최근 활동 | 요약 카드 8개, 도넛 3개, 막대, 표 |

- 관리자 API 는 맨 앞에서 `_require_admin()` 으로 **역할을 검사**한다. 학생이 호출하면 403.
- 학생 수만큼 DB 를 반복 조회하지 않고, **테이블별로 한 번씩** 가져와 파이썬에서 묶어 계산한다(학생이 늘어도 느려지지 않게).

### 4-4. 학생 상태 판정 (관리자)

```python
# backend/app/admin.py
STALL_DAYS = 7

def _student_status(enrolled_count, completed, total, last_activity, first_enrolled_at, now):
    if enrolled_count == 0:            return "미시작"
    if total and completed >= total:   return "완료"
    reference = last_activity or first_enrolled_at          # 활동이 없으면 수강 시작일 기준
    if reference and now - reference > timedelta(days=STALL_DAYS):
        return "정체"
    if completed == 0:                 return "미시작"
    return "진행중"
```

| 상태 | 조건 | 관리자가 할 일 |
|---|---|---|
| 미시작 | 수강 과목 없음, 또는 완료 단계 0 | 학습 시작 안내 |
| 진행중 | 일부 완료, 최근 7일 내 활동 | 지켜보기 |
| 정체 | 미완료 + 7일 넘게 활동 없음 | 먼저 연락 |
| 완료 | 수강 과목 전체 단계 완료 | 다음 과목 권유 |

- "마지막 활동"은 로그인 기록이 아니라 **단계 완료 + 포인트 적립** 시각으로 본다. 접속만 하고 아무것도 안 한 경우는 활동으로 치지 않는다.

### 4-5. 도넛 차트를 그리는 원리 (학생 개인 현황)

```
원 둘레 = 2 × π × 반지름
조각 길이 = (값 ÷ 전체) × 둘레
stroke-dasharray  = "조각 길이  둘레"     → 테두리를 조각만큼만 그림
stroke-dashoffset = -(앞 조각 길이 합)    → 다음 조각을 이어서 그림
rotate(-90)                              → 12시 방향에서 시작
```

## 5. 동작 흐름 예시

```
1. 학생이 XSS DOM 수강신청 → 기록 없음 → 0% (시작 전, "학습 시작" 버튼)
2. 확인 문제 통과 → concept 완료 + 확인문제 표시 → 33% (✔개념)
3. 하·중 통과 → 레벨 표시만 생김 → 여전히 33% (실습은 하·중·상 모두 필요)
4. 상 통과 → practice 완료 → 67% (✔개념 ✔실습, "이어하기")
5. 퀴즈 70% → defense 완료 → 100% (✔✔✔, "복습하기")
6. 관리자 화면: 이 학생의 해당 과목 100%, 수강 과목 전부 끝나면 상태 "완료"
   7일 넘게 아무것도 안 하면 상태 "정체"
```

## 6. 주의점과 한계

- **확인 문제 문항이 비어 있으면** 1회차를 완료할 수 없어 진도율이 최대 67%에서 멈춘다. `concept_check.py` 에 문항을 넣으면 해결된다.
- **수강신청하면 그 과목 진도는 0%로 초기화**된다. 다시 신청한 과목은 처음부터다.
- **진도율이 33%씩 움직인다.** 단계가 3개뿐이라 중간 값(예: 50%)은 없다.
- "정체" 판단은 **활동 기록 기준**이라, 화면만 오래 보고 미션을 안 한 경우도 정체로 표시될 수 있다.
- 단계 순서는 강제하지 않는다. 실습을 개념 학습보다 먼저 끝낼 수도 있어, 관리자 단계별 진행률이 꼭 줄어드는 모양은 아니다.

## 7. 핵심 정리

- 과목 진도율 = **완료 단계 수 ÷ 3 × 100**. 단계는 개념 학습 · 실습 성공 · 방어 퀴즈.
- 진도율은 저장하지 않고 `task_progress` 기록으로 **매번 계산**해서, 원본이 하나라 모든 화면의 숫자가 같다.
- `effective_task_rows` 가 지금 규칙(확인 문제 통과, 하·중·상 통과)에 맞는 완료만 센다.
- 관리자 화면은 같은 계산으로 학생별 진도와 상태(진행중·정체·완료·미시작)를 보여준다.
- 발표용 한 문장: **"진도율은 단계 완료 기록 하나를 원본으로 매번 계산하고, 판정 함수를 모든 화면이 공유해 학생 화면과 관리자 화면의 숫자가 항상 일치한다."**
