# 05. 진도율 기준 변경 — 실습 레벨 통과만 반영

> 작성: 2026-10-09 · 오현명
> 관련: `01_학습진도_진도율.md` (이전 기준: 미션 3개)

---

## 1. 요약

| | 변경 전 | 변경 후 |
|---|---|---|
| 진도율 기준 | 미션 3개(개념 학습 · 실습 미션 · 퀴즈) | **실습 레벨 4개(하 · 중 · 상 · 안전) 통과** |
| 과목 1개 100% | 미션 3개 모두 완료 | 실습 4레벨 모두 통과 |
| 레벨 1개 통과 | 진도 변화 없음 | +25% (과목 기준) |
| 개념 확인 문제 · 퀴즈 · 미션 | 진도율에 포함 | **진도율에 포함하지 않음** (보상 · 학습 점검용으로만 유지) |

- 학생이 "실습을 해야 진도가 오른다"는 흐름이 직관적이도록, 진도율을 **실습 페이지 통과 여부**로만 계산한다.
- 미션 탭(1~3회차)과 보상, 퀴즈는 그대로 동작한다. 진도율 계산에서만 빠졌다.
- DB 구조 변경 없음. 기존에 쌓인 레벨 통과 기록(`task_progress` 의 `tier_*`)을 그대로 사용하므로 **이미 통과한 레벨은 바로 진도에 반영**된다.

---

## 2. 계산 방법

```
과목 진도율   = 통과한 레벨 수 / 4 × 100
전체 진도율   = (수강 과목들의 통과 레벨 합) / (수강 과목 수 × 4) × 100
```

예: 2과목 수강, Command Injection 4레벨 통과 · CSRF 0레벨 → 과목 100% / 0%, 전체 4/8 = 50%

## 3. 화면 변화

| 화면 | 변경 |
|---|---|
| 학습 진도 (`/chapters`) | 안내 문구 · 과목 카드 체크 표시가 "개념 · 실습 · 퀴즈" → **"하 · 중 · 상 · 안전"**, "실습 레벨 n/4 통과" |
| 학습 대시보드 | "완료 미션" → **"통과한 실습 레벨"**, 과목별 "실습 레벨 n/4 통과" |
| 과목 상세 상단 | "n/3 미션 완료" → **"실습 레벨 n/4 통과"** |
| 관리자 · 학생 진도 | 과목별 % · 전체 %가 레벨 기준, "단계별 진행률" → **"실습 레벨별 통과율"**(하→중→상→안전 이탈 확인), 학생 상세 표 열이 레벨별 통과 날짜 |
| 관리자 · 학생 개인 현황 | 진도 · 레벨별 통과 · 과목별 통과 날짜가 레벨 기준. 최근 활동에 "실습 ○ 레벨 통과" 표시 |
| 미션 안내 | 1회차(개념 학습) 보상 문구를 실제와 맞게 "과목별 경험치 또는 포인트"로 수정 |

## 5. 확인 (실제 Flask 앱 + 테스트 DB)

| 상황 | 과목 진도 | 대시보드(2과목 수강) |
|---|---|---|
| 수강 직후 | 0% | 0/8 · 0% |
| 개념 확인 문제 통과 | **0% (변화 없음)** ✅ | 0% |
| 하 · 중 통과 | 50% | 2/8 · 25% |
| 4레벨 + 퀴즈 통과 | **100%** (퀴즈 무관) ✅ | 4/8 · 50% |

- 관리자 학생 현황 50% · 퍼널(하 1 · 중 1 · 상 1 · 안전 1) · 개인 현황 50% — 학생 화면과 일치 ✅
- 프론트엔드 `vite build` ✅

### 직접 확인

```bash
docker compose restart backend
```

학생으로 한 과목의 하 레벨만 통과 → 학습 진도 화면에서 그 과목 25%, "하" 체크 표시 확인.
