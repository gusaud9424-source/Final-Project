# 01. 학습 진도 화면 (과목별 진도율)

## 1. 요약

- 비어 있던(stub) `/chapters` 화면을 **학습 진도** 화면으로 구현했다 (헤더 탭명 "과목 선택" → "학습 진도").
- 8개 과목을 **초급 → 중급 → 고급** 순서로 묶어 카드로 보여준다.
- 수강 중인 과목은 **진도율 바 · 완료 수 · 단계별(개념/실습/퀴즈) 체크**를 표시한다.
- 상단에 **전체 진도율**을 보여주며, 계산 방식은 학습 대시보드의 "학습 요약"과 같다.
- 버튼은 상태에 따라 학습 시작 / 이어하기 / 복습하기 / 수강신청하러 가기로 바뀐다.

---

## 2. 개념 설명 (비유)

학원 복도에 붙은 **수강생 진도표**와 같다.

- 과목마다 칸이 3개(개념 · 실습 · 퀴즈) 있고, 끝낸 칸에 체크를 한다.
- 체크한 칸 수를 보고 "이 과목은 2/3, 67% 진행" 처럼 진도를 계산한다.
- 반 편성표(초급반 → 중급반 → 고급반) 순서대로 붙어 있어서 어떤 순서로 들으면 되는지 한눈에 보인다.
- 아직 등록하지 않은 과목은 "미수강"으로 표시되고, 등록 창구(수강신청)로 안내한다.

웹에서는 체크 칸이 **`task_progress` 테이블의 한 줄**, 진도표가 **학습 진도 화면**이다.

---

## 3. 용어 설명

| 용어 | 뜻 |
|---|---|
| 진도율 | 과목의 3단계 중 완료한 비율. `완료 단계 수 ÷ 3 × 100` (반올림) |
| task_progress | 사용자가 과목의 단계를 완료할 때마다 쌓이는 기록 테이블 (`user_id`, `course_id`, `task_key`) |
| TASK_KEYS | 과목 단계 키 목록. `concept`(개념 학습) · `practice`(실습 성공) · `defense`(퀴즈 풀기) |
| doneKeys | 이번에 추가한 응답 필드. 해당 과목에서 완료한 단계 키 목록 (예: `["concept", "practice"]`) |
| 전체 진도율 | 수강 중인 모든 과목의 완료 단계 합 ÷ 전체 단계 합 |
| stub | 경로만 연결되어 있고 실제 내용은 없는 임시 화면 |

## 4. 화면 & 동작

### 화면

```
┌──────────────────────────────────────────────────────────────┐
│ 학습 진도                                  전체 진도율      47% │
│ 초급 → 중급 → 고급 순서로 학습하세요.        ███████░░░░░░░░    │
│                                   수강 중 5/8과목 · 단계 7/15 완료 │
└──────────────────────────────────────────────────────────────┘
[초급] 4과목
┌─────────────────────────┐ ┌─────────────────────────┐
│ >_                학습 중 │ │ { }               미수강 │
│ Command Injection        │ │ XSS (DOM)                │
│ ████████████░░░░░        │ │ 수강신청 후 학습할 수      │
│ 2/3 완료 · 67%           │ │ 있습니다.                 │
│ ✔개념 ✔실습 ○퀴즈        │ │                          │
│ [      이어하기      ]   │ │ [ 수강신청하러 가기 ]     │
└─────────────────────────┘ └─────────────────────────┘
[중급] 3과목 ...
[고급] 1과목 ...
```

- 카드 상태 라벨과 버튼 문구는 진도율로 정한다 (6장 표 참고).
- 수강 중 과목 버튼 → 과목 상세(`/dashboard/courses/<slug>`), 미수강 과목 버튼 → 수강신청(`/enroll`).
- 관리자 계정은 진도가 집계되지 않으므로 안내 문구만 보이고 진도 바는 표시하지 않는다.
- 색은 모두 `var(--sq-*)` 토큰만 사용했고, 진행 바 규격은 학습 대시보드와 같다.

### 관련 파일

| 파일 | 역할 |

## 5. 동작 원리 (진도 표시 흐름)

```
[1] 학습 진도 화면 진입 (/chapters)
      │  GET /api/v1/enrollments      → 수강 중인 과목 slug 목록
      │  GET /api/v1/dashboard        → 수강 과목별 진도(completed/total/percent/doneKeys)
      ▼
[2] 프런트: enroll 스토어의 8개 과목 + 진도 정보를 slug 기준으로 합침
      - 수강 중 & 진도 있음 → 진도 바 · 단계 체크 표시
      - 미수강 → "미수강" + 수강신청 안내
      ▼
[3] 난이도(초급 → 중급 → 고급) 순서로 묶어 카드 렌더링
      ▼
[4] 상단 전체 진도율 = 수강 과목 완료 단계 합 ÷ 전체 단계 합
```

### 왜 이렇게 설계했나

- **새 API를 만들지 않았다.** 학습 대시보드가 이미 과목별 진도를 `task_progress` 기준으로 계산해 준다. 같은 API를 재사용해서 대시보드와 학습 진도 화면의 숫자가 **항상 일치**하도록 했다.
- **`doneKeys` 한 필드만 추가**: 기존 응답은 "몇 개 완료"만 알려줘서 어떤 단계가 남았는지 알 수 없었다. 완료한 단계 키 목록을 추가해 카드에 개념 · 실습 · 퀴즈 체크를 표시한다. 기존 필드는 그대로라 대시보드에 영향이 없다.
- **과목 목록은 스토어 기준**: 대시보드 응답에는 수강 중인 과목만 있으므로, 미수강 과목까지 보여주려면 8개 과목을 모두 가진 `enroll` 스토어를 기준으로 진도 정보를 덧붙인다.
- **난이도 순서 고정**: 피드백("하 → 중 → 상 순서로 학습")을 반영해 초급 → 중급 → 고급 그룹으로 정렬했다.
- **아이콘 보정**: 미수강 과목은 대시보드 응답이 없어 아이콘을 받을 수 없으므로, `seed.py` 의 과목 아이콘과 같은 값을 프런트에 매핑해 둔다.

---

## 6. 난이도(단계) 대신 — 진도 상태별 표시

이 기능은 공격/방어 실습이 아니라 학습 현황 기능이므로, "난이도" 대신 **진도 상태**로 정리한다.

| 상태 라벨 | 조건 | 진도 표시 | 버튼 |
|---|---|---|---|
| 미수강 | 수강신청 안 함 | 안내 문구만 | 수강신청하러 가기 (→ `/enroll`) |
| 시작 전 | 수강 중, 0% | 빈 진도 바 | 학습 시작 |
| 학습 중 | 1 ~ 99% | 진도 바 + 단계 체크 | 이어하기 |
| 완료 | 100% (3/3) | 가득 찬 진도 바 | 복습하기 |

---

## 7. 핵심 정리

- 학습 진도 화면은 **8개 과목을 난이도 순서로** 보여주고, 수강 중인 과목의 **진도율과 단계별 완료 여부**를 표시한다.
- 진도는 **`task_progress` 3단계(개념 · 실습 · 퀴즈)** 기준이며, 대시보드 API를 재사용해 숫자가 대시보드와 일치한다.
- 백엔드는 응답에 **`doneKeys`** 한 필드만 추가했고, 기존 필드와 화면에는 영향이 없다.
- 상태(미수강 / 시작 전 / 학습 중 / 완료)에 따라 버튼이 바뀌어 다음 행동을 바로 안내한다.
