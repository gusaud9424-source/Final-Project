# 02. 전체 학생 현황 (관리자 수강생 진도 페이지)

> 대상: 웹 보안을 처음 배우는 입문자
> 목표: 관리자가 보는 "전체 학생 현황" 화면이 어떤 지표로 구성되고, 서버가 그 숫자를 어떻게 계산하는지 이해한다.
> 작성: 2026-10-04 · 오현명

---

## 1. 요약

- 관리자 학습 대시보드의 "전체 학생 현황"을 **요약 카드 → 과목별 진도 → 단계별 진행률 → 학생별 진도 표 → 학생 상세** 순서로 개편했다.
- 새 API `GET /api/v1/admin/progress` 한 번으로 화면에 필요한 모든 숫자를 서버에서 계산해 내려준다.
- 학생마다 **진행중 / 정체 / 완료 / 미시작** 상태를 붙이고, **7일 이상 활동이 없으면 "정체"**로 표시한다.
- 학생별 표는 검색 · 상태 필터 · 정렬 · CSV 다운로드를 지원하고, 행을 누르면 단계별 완료일이 펼쳐진다.
- 관리자 페이지의 "학생 진도" 탭도 같은 컴포넌트를 사용하므로 함께 바뀌었다.

---

## 2. 개념 설명 (비유)

학원 원장실의 **반 운영 현황판**과 같다.

- 맨 위에는 "전체 원생 수, 평균 진도, 이번 주 출석한 학생, 연락이 끊긴 학생" 같은 **핵심 숫자**가 있다(요약 카드).
- 그 아래에는 **과목별 진도 그래프**가 있어 어떤 과목이 어려운지 보인다.
- "개념 수업은 다 들었는데 실습에서 많이 멈춘다" 같은 **단계별 흐름**도 본다(단계별 진행률).
- 마지막으로 **원생 명단**에서 한 명씩 진도를 확인하고, 이름을 누르면 그 학생의 **상세 기록**을 본다.
- 일주일 넘게 오지 않은 학생은 빨간 표시를 붙여 먼저 연락한다(정체 학생).

---

## 3. 용어 설명

| 용어 | 뜻 |
|---|---|
| 진도율 | 과목 3단계(개념·실습·퀴즈) 중 완료 비율. 학생 전체 진도율 = 완료 단계 합 ÷ (수강 과목 수 × 3) |
| 평균 진도율 | 수강 과목이 있는 학생들의 전체 진도율 평균 |
| 최근 7일 학습 | 마지막 활동이 7일 이내인 학생 수 |
| 마지막 활동 | 단계 완료 시각(`task_progress`)과 포인트 적립 시각(`point_ledger`, 출석 포함) 중 가장 최근 |
| 정체 | 수강 중이고 미완료인데 마지막 활동(없으면 수강 시작일)이 7일보다 오래된 상태 |
| 단계별 진행률 | 전체 수강 건(학생×과목) 중 각 단계를 완료한 비율 |
| 이탈 | 앞 단계보다 다음 단계 완료 비율이 떨어진 정도(%p) |
| CSV | 쉼표로 구분한 표 파일. 엑셀에서 열 수 있다 |

## 4. 화면 & 동작

### 화면

```
전체 학생 현황
┌────────┐┌────────┐┌────────┐┌──────────────────────┐
│전체 수강생││평균 진도율││최근 7일 학습││정체 학생(7일 이상 활동 없음)│
│  2명   ││  57%   ││  2명   ││         0명          │
└────────┘└────────┘└────────┘└──────────────────────┘
┌ 과목별 평균 진도율 ─────────────────┐┌ 단계별 진행률 ──────────┐
│[초급] Command Injection ████▌ 84% 수강2·완료1││개념 학습  3/7 · 43%  │
│[초급] XSS (Reflected)   ██    33% ...      ││실습 성공  6/7 · 86%  │
│ ...                                        ││퀴즈 통과  2/7 · 29%  │
│[고급] SQL Injection (Blind)     0% ...     ││⚠ 퀴즈 통과 단계 이탈 57%p│
└────────────────────────────────────┘└───────────────────────┘
┌ 학생별 진도          [이름·아이디 검색] [상태: 전체▾] [CSV] ┐
│ 학생▲   CMD  XSS-R XSS-D XSS-S SQLi CSRF Upload Blind 전체 마지막 활동 상태 │
│ 시연용   67%  33%   -     -     33%  67%  33%    -    47%  어제    진행중│
│  └ demo1@... · 149P · 출석 1일 · 단계 7/15                        │
│    과목 │ 개념 학습      │ 실습 성공      │ 퀴즈 통과 │ 진도          │
│    CMD  │ ✔ 2026-09-30  │ ✔ 2026-10-03  │ 미완료    │ 67%          │
└──────────────────────────────────────────────────────┘
```

- 과목은 **초급 → 중급 → 고급** 순서로 정렬한다.
- 표의 칸 색: 100% = 초록, 1~99% = 연파랑, 0% = 회색, 미수강 = `-`.
- 정렬: 학생 이름 · 전체 진도율 · 마지막 활동 열 제목을 누르면 오름/내림차순이 바뀐다.
- CSV는 **현재 검색·필터 결과**를 그대로 저장하며, 엑셀 한글 깨짐을 막기 위해 BOM을 붙인다.
- 색은 모두 `var(--sq-*)` 토큰만 사용했다.

### 관련 파일

| 파일 | 역할 |
|---|---|
| `backend/app/admin.py` | `GET /api/v1/admin/progress` 집계 API, 상태 판정 `_student_status()` |

## 5. 동작 원리 (집계 흐름)

```
[1] 관리자가 학습 대시보드 진입
      │  GET /api/v1/admin/progress  (관리자 역할 검사, 아니면 403)
      ▼
[2] 서버: 필요한 데이터를 한 번에 조회 (학생 수만큼 반복 조회하지 않음)
      - 과목(난이도 순), 학생, 수강, task_progress
      - point_ledger: 포인트 합계 · 출석 횟수 · 마지막 적립 시각 (GROUP BY)
      ▼
[3] 서버: 학생별 계산
      - 과목별 진도율 + 단계별 완료 시각
      - 전체 진도율, 마지막 활동, 상태(진행중/정체/완료/미시작)
      ▼
[4] 서버: 전체 집계
      - 요약(학생 수 · 평균 진도율 · 최근 7일 학습 · 정체 수)
      - 과목별(수강 인원 · 평균 진도율 · 완료 인원)
      - 단계별(전체 수강 건 중 단계 완료 수/비율)
      ▼
[5] 프런트: 받은 숫자를 카드·막대·표로 그림
      - 검색 · 필터 · 정렬 · 상세 펼침 · CSV 는 브라우저에서 처리 (추가 요청 없음)
```

### 상태 판정 규칙

```
수강 과목 0개                         → 미시작
완료 단계 = 전체 단계                  → 완료
(마지막 활동 또는 수강 시작일) > 7일 전  → 정체
완료 단계 0개                         → 미시작
그 외                                → 진행중
```

### 왜 이렇게 설계했나

- **계산은 서버에서**: 학생 수가 늘어도 프런트가 여러 API를 조합할 필요 없이 한 번의 요청으로 끝난다. 학생마다 쿼리를 날리지 않고 테이블별로 한 번씩 조회한 뒤 파이썬에서 묶어 계산한다.
- **진도 기준 통일**: 학생용 대시보드·학습 진도 화면과 같은 `task_progress` 3단계 기준을 쓴다. 그래서 학생 화면 숫자와 관리자 화면 숫자가 어긋나지 않는다.
- **마지막 활동 = 단계 완료 + 포인트 적립**: 로그인 기록 테이블이 없으므로, 남아 있는 활동 흔적(단계 완료, 출석·보상 포인트) 중 가장 최근 시각을 쓴다. 단순 접속만 하고 아무것도 안 한 경우는 활동으로 보지 않는다.
- **정체 기준 7일**: 일주일 단위 학습 주기를 기준으로 삼았다. 값은 `admin.py` 의 `STALL_DAYS` 상수 하나만 바꾸면 된다.
- **단계별 진행률로 콘텐츠 점검**: 어느 단계에서 비율이 크게 떨어지는지 보면 그 단계의 난이도·설명을 보완할 근거가 된다. 실습은 개념 학습 없이도 성공할 수 있어 단계 비율이 꼭 줄어드는 순서는 아니다.
- **관리자 전용**: 다른 관리자 API와 같이 역할 검사를 거치며, 학생 계정이 호출하면 403이다.

## 6. 난이도(단계) 대신 — 학생 상태별 표시

이 기능은 공격/방어 실습이 아니라 관리 화면이므로, "난이도" 대신 **학생 상태**로 정리한다.

| 상태 | 조건 | 배지 색 | 관리자 행동 예시 |
|---|---|---|---|
| 진행중 | 수강 중, 최근 7일 내 활동 | 파랑 | 그대로 지켜본다 |
| 정체 | 미완료 + 7일 넘게 활동 없음 | 빨강 | 먼저 연락 · 학습 독려 |
| 완료 | 수강 과목 전체 단계 완료 | 초록 | 다음 난이도 과목 수강 권유 |
| 미시작 | 수강 과목 없음 / 아직 완료 단계 없음 | 회색 | 수강신청 · 첫 단계 안내 |

## 7. 핵심 정리

- 전체 학생 현황은 **요약 → 과목별 → 단계별 → 학생별 → 학생 상세** 순서로 점점 자세해진다.
- 모든 숫자는 **`GET /api/v1/admin/progress`** 한 번으로 서버가 계산하며, 진도 기준은 학생 화면과 같은 **3단계(개념·실습·퀴즈)**다.
- **7일 이상 활동이 없는 미완료 학생은 "정체"**로 표시해 관리자가 먼저 챙길 수 있게 했다.
- 검색 · 필터 · 정렬 · CSV 다운로드 · 상세 펼침은 브라우저에서 처리한다.

---

## 8. 검증

- 백엔드 `admin.py` 문법 검사 통과, 프런트 `StudentsOverview.vue` Vite 모듈 로드 통과
- 브라우저(관리자 계정)에서 확인:
  - 요약: 전체 수강생 2명 · 평균 진도율 57%(demo1 47%, student1 67%의 평균) · 최근 7일 학습 2명 · 정체 0명
  - 과목별: Command Injection 84%(수강 2 · 완료 1) 등 초급 → 고급 순서 표시
  - 단계별: 개념 3/7 · 실습 6/7 · 퀴즈 2/7, "퀴즈 통과 단계 이탈 57%p" 표시
  - 학생 행 클릭 → 이메일 · 포인트 149P · 출석 1일 · 단계 7/15, 과목별 단계 완료일 표시
- CSV 다운로드는 **확인 필요** (브라우저 다운로드는 이 세션에서 실행하지 않음)
