# 03. 통과한 레벨 표시 · 레벨 보상 이름 변경

> 대상: 웹 보안을 처음 배우는 입문자
> 목표: 통과한 레벨이 화면에서 계속 "통과"로 보이게 한 이유와, 레벨 보상 이름 규칙을 이해한다.
> 작성: 2026-10-06 · 오현명
> 📘 레벨 구조 전체는 `02_난이도_학습구조_개념설명.md` 참고.

---

## 1. 요약

- **문제**: 하 레벨을 통과한 뒤 중 레벨을 눌렀다가 다시 하 레벨로 돌아오면, 결과 칸이 "아직 실행 결과가 없습니다"로 비어 **처음부터 다시 하는 것처럼** 보였다. (서버에는 통과 기록이 남아 있었지만 화면이 보여주지 않았다.)
- **수정**: 통과한 레벨을 선택하면 결과 칸 맨 위에 **"✅ 이 레벨은 통과했습니다"** 를 항상 표시한다. 다른 레벨로 갔다 와도, 새로고침해도 유지된다.
- 통과한 레벨에서 다시 연습할 수는 있지만 **통과 기록과 보상에는 영향이 없다**.
- **레벨 보상 이름**: `Command Injection 실습 하 레벨` → **`Command Injection 하(Low)`** 형식으로 변경. (중 = `중(Medium)`, 상 = `상(High)`, 안전 = `안전(Impossible)`)
- 이미 만들어진 보상의 이름은 그대로이고, **새로 생기는 보상부터** 적용된다.

---

## 2. 개념 설명 (비유)

**게임 스테이지 선택 화면의 "CLEAR" 도장**과 같다.

- 깬 스테이지에 다시 들어가도 "CLEAR" 도장은 그대로 붙어 있다.
- 다시 플레이해 볼 수는 있지만, 처음 깼을 때 받은 보상은 다시 주지 않는다.

---

## 3. 용어 설명

| 용어 | 뜻 |
|---|---|
| 통과 기록 | 서버 `task_progress` 의 `tier_<레벨>` 행. 레벨 상태 API 의 `cleared: true` |
| `selectedTierCleared` | 지금 선택한 레벨이 통과 상태인지 계산하는 화면 값 |
| reason | 보상 이름(보물상자 목록에 보이는 글자) |

---

## 4. 화면 & 동작

```
결과
┃ ✅ 이 레벨은 통과했습니다          ← 통과한 레벨이면 항상 표시
[성공] (직전 실행 결과가 있으면 아래에 표시)
```

| 상황 | 결과 칸 |
|---|---|
| 통과 안 한 레벨 · 실행 전 | "아직 실행 결과가 없습니다." |
| 통과한 레벨 · 실행 전 (다른 레벨 갔다 옴 / 새로고침) | "✅ 이 레벨은 통과했습니다" |
| 통과한 레벨 · 다시 실행 | 통과 표시 + 새 실행 결과 |

보물상자 표시 예:

```
🎁 Command Injection 하(Low)      경험치 +32
🎁 Command Injection 중(Medium)   경험치 +55
```

### 관련 파일

| 파일 | 역할 |
|---|---|
| `frontend/src/views/ChapterDetailView.vue` | `selectedTierCleared` 계산, 결과 칸 통과 표시, 스타일 |
| `backend/app/courses.py` | `_roll_tier_reward` 보상 이름 `<과목> <레벨>(<영문>)`, `_TIER_NAMES` |

## 5. 동작 원리

```javascript
const selectedTierCleared = computed(
  () => !!tierList.value.find((t) => t.key === selectedTier.value)?.cleared
);
```

- `tierList` 는 화면을 열 때 서버(`GET /practice/tiers`)에서 받고, 실행할 때마다 응답으로 갱신된다.
- 통과 여부를 화면 메모리가 아니라 **서버 기록**으로 판단하므로 새로고침해도 사라지지 않는다.

```python
_TIER_NAMES = {"low": "Low", "medium": "Medium", "high": "High", "impossible": "Impossible"}
reason = f"{course.title} {TIER_LABELS[tier]}({_TIER_NAMES[tier]})"   # Command Injection 하(Low)
```

### 왜 이렇게 했나

- **학습 상태를 정확히 보여주기**: 통과한 레벨이 비어 보이면 학생은 "기록이 사라졌다"고 오해한다.
- **보상 이름 통일**: 화면의 레벨 표기(하 (Low))와 보물상자 이름을 같은 형식으로 맞췄다.
- **보상 규칙은 유지**: 레벨 보상은 계정당 한 번이다. 수강취소 후 다시 신청해 통과해도, 이미 받은 레벨 보상은 다시 생기지 않는다(실습 결과에 "이미 이 레벨의 클리어 보상을 받았습니다" 표시).

---

## 6. 핵심 정리

- 통과한 레벨은 결과 칸에 **"✅ 이 레벨은 통과했습니다"** 가 항상 보인다(서버 기록 기준).
- 새 레벨 보상 이름은 **`<과목> 하(Low)`** 형식이다.

## 8. 버그 수정 — 중 → 하 다시 누르면 하가 안 눌림

**증상**: 하를 통과한 상태에서 중을 눌렀다가 하를 다시 누르면 화면이 바뀌지 않음(하가 안 눌리는 것처럼 보임).

**원인**: 결과 칸 템플릿의 `v-else` 짝이 잘못 맞물림.

```html
<p v-if="selectedTierCleared">✅ 이 레벨은 통과했습니다</p>
<p v-if="!lastResult && !selectedTierCleared">아직 실행 결과가 없습니다.</p>
<div v-else class="sq-practice__result"> {{ lastResult.success }} ... </div>
```

- `v-else`는 **바로 앞 `v-if`**(둘째 줄)의 반대다.
- 레벨을 바꾸면 `watch(selectedTier)`가 `lastResult = null`로 비운다.
- 통과한 하로 돌아오면 `selectedTierCleared = true` → 둘째 줄 조건 false → `v-else` 결과 상자가 그려짐
- 그런데 `lastResult`가 `null`이라 `lastResult.success`에서 **TypeError** → Vue 렌더링이 멈춰 버튼을 눌러도 화면이 갱신되지 않음.
- 중은 아직 통과 전이라 "아직 실행 결과가 없습니다"가 보여 문제가 없었음 → 통과한 레벨로 돌아갈 때만 발생.

**수정**: 결과 상자를 실제 결과가 있을 때만 그리도록 변경.

```html
<div v-else-if="lastResult" class="sq-practice__result">
```

| 상태 | 통과 표시 | "결과 없음" 문구 | 결과 상자 |
|---|---|---|---|
| 통과 레벨, 결과 없음 | ✅ | – | – (수정 전: 오류) |
| 통과 레벨, 방금 실행 | ✅ | – | ✅ |
| 미통과, 결과 없음 | – | ✅ | – |
| 미통과, 방금 실행 | – | – | ✅ |

**교훈**: `v-if`를 두 개 연달아 쓰고 `v-else`를 붙이면 마지막 `v-if`에만 묶인다. 객체 속성을 읽는 블록은 그 객체가 있을 때만 렌더링되게 조건을 직접 건다.
