# 04. 안전(Impossible) 레벨 통과 처리 수정

> 작성: 2026-10-09 · 오현명
> 관련: `01_난이도_하중상_학습구조.md`, `03_통과표시_보상명.md`

---

## 1. 증상

- XSS(Reflected · DOM · Stored) 안전 레벨에서 공격을 입력하고 [Submit] 해도 레벨 카드가 계속 **"진행 가능"** 으로 보였다. 새로고침해야 "통과"로 바뀌었다.
- 반대로 Stored XSS · CSRF · Blind SQLi 는 안전 레벨을 **열기만 해도** 통과 처리됐다(화면이 처음 열릴 때 자동으로 보내는 조회 요청까지 "시도"로 셌기 때문).

## 2. 원인

| 증상 | 원인 |
|---|---|
| XSS 통과 표시 안 됨 | XSS 실습은 스크립트가 **실행됐을 때(verify)만** 결과를 화면에 넘긴다. 안전 레벨은 실행이 안 되니 서버가 `tierCleared=true` 를 돌려줘도 화면이 그 값을 받지 못함 |
| 열기만 해도 통과 | 서버 규칙이 "안전 레벨이면 요청 1회 = 통과" 였고, `render`(빈 입력) · `info` · `reset` 같은 자동 요청도 포함됨 |

## 3. 수정

| 파일 | 변경 |
|---|---|
| `backend/app/courses.py` | `_is_attempt()` 추가: 안전 레벨은 **학생이 직접 공격을 시도한 요청**만 통과로 인정. `info` · `leak_token` · `reset` · `verify` 와 빈 입력 `render` 제외 |
| `frontend/src/components/practice/XssPractice.vue` | 실행 응답에 `tierCleared` 가 있으면 즉시 결과로 전달 → 레벨 카드 "통과", 다음 안내 문구, 보상 알림 |
| `frontend/src/components/practice/StoredXssPractice.vue` | 위와 동일 |

통과 시 결과 문구: "방어 확인 완료 — 입력한 < > 가 \&lt; \&gt; 로 인코딩되어 글자로만 표시되고 스크립트는 실행되지 않았습니다."

## 4. 안전 레벨 클리어 방법 (학생 안내)

1. 하 · 중 · 상에서 성공했던 공격을 **그대로** 입력한다. 예: `<script>alert(1)</script>`, `<img src=x onerror=alert(1)>`
2. [Submit] (Stored 는 Name · Message 입력 후 [Sign Guestbook])
3. 미리보기에 입력이 **글자 그대로** 보이고 alert 이 뜨지 않음 → 레벨 카드가 "통과"로 바뀜
4. [페이지 소스 보기] 로 `<` 가 `&lt;` 로 바뀐 것을 확인하고 힌트의 방어 원리를 정리

> `&lt;script&gt;` 처럼 이미 인코딩된 글자를 입력해도 통과는 되지만, 방어를 확인하려면 **진짜 공격 문자열**을 넣어 보는 것이 학습 목적에 맞다.

## 5. 확인

- `_is_attempt()` 11개 경우 기대값 일치 (빈 render · info · reset · leak_token → 미인정 / 입력 있는 render · post · attack · probe · submit · 명령어 문자열 → 인정)
- 프론트엔드 `vite build` 성공
- 실제 화면(Docker, 보안 헤더 적용 후): XSS (Reflected) 안전 레벨 "통과" 표시, 하 레벨 `<script>alert(1)</script>` 재시도 "성공" 확인 (2026-10-09)
