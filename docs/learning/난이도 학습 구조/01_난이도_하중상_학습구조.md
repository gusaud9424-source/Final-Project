# 01. 난이도(하 → 중 → 상) 학습 구조 재정리

> 대상: 웹 보안을 처음 배우는 입문자
> 목표: 실습 레벨이 왜 순서대로만 열리게 바뀌었고, 화면과 서버가 그 순서를 어떻게 지키는지 이해한다.

---

## 1. 요약

- **발표 피드백**: "핵심 취약점을 레벨(하 > 중 > 상)로 접근해야 하는데 지금은 레벨이 섞여 있다", "클라이언트가 레벨 순서대로 학습해야 한다".
- **변경 전**: 실습 화면의 난이도가 라디오 버튼이라 처음부터 **아무 레벨이나** 고를 수 있었다.
- **변경 후**: 레벨을 **스테퍼(하 → 중 → 상 → 안전)** 로 바꾸고, **앞 레벨을 통과해야 다음 레벨이 열린다**.
- 레벨마다 의미를 고정했다: 하 = 방어 없음 · 중 = 단순 방어 · 상 = 강화된 방어 · 안전 = 올바른 방어 코드.
- 순서는 화면뿐 아니라 **서버에서도 강제**한다. 잠긴 레벨의 실행·힌트 요청은 403으로 거부된다.
- 별도 테이블 없이 기존 `task_progress` 에 `tier_low` 같은 키로 저장해 **DB 마이그레이션이 필요 없다**.

---

## 2. 개념 설명 (비유)

**게임의 스테이지 잠금**과 같다.

- 1스테이지(하)를 깨야 2스테이지(중)가 열리고, 2스테이지를 깨야 3스테이지(상)가 열린다.
- 마지막 "안전" 스테이지는 보스전이 아니라 **정답 해설 영상**에 가깝다. 공격이 왜 막히는지 직접 보면 통과한다.
- 스테이지를 건너뛰면 "앞에서 배운 기술이 왜 다음 단계에서 막히는지"를 놓치게 된다. 그래서 순서를 고정했다.

---

## 3. 용어 설명

| 용어 | 뜻 |
|---|---|
| 레벨(tier) | 같은 취약점 안의 단계. `low`(하) · `medium`(중) · `high`(상) · `impossible`(안전) |
| 통과(cleared) | 하·중·상은 실습 성공, 안전은 1회 이상 시도해 방어를 확인한 상태 |
| 잠김(locked) | 바로 앞 레벨을 아직 통과하지 않아 선택·실행할 수 없는 상태 |
| 스테퍼 | 단계를 번호 순서대로 나열하고 현재·완료·잠김을 표시하는 UI |
| 403 Forbidden | 요청은 이해했지만 권한·조건이 맞지 않아 거부한다는 HTTP 응답 |

## 4. 화면 & 동작

### 4-1. 실습 화면 (변경 핵심)

```
실습
┌────────────┐┌────────────┐┌────────────┐┌────────────┐
│ ✓          ││ 2          ││ 🔒         ││ 🔒         │
│ 하 (Low)   ││ 중 (Medium)││ 상 (High)  ││ 안전       │
│ 통과       ││ 진행 가능   ││ 잠김       ││ 잠김       │
└────────────┘└────────────┘└────────────┘└────────────┘
┃ 중 레벨 — 단순한 방어가 추가됩니다. 그 방어가 왜 충분하지 않은지 생각해 봅니다.
┃ 하 레벨 통과! 이제 중 레벨이 열렸습니다.        ← 통과 직후 안내
[ 실습 화면 (DVWA 재현) ]
[ 힌트 보기 ]  ← 현재 레벨의 힌트만 제공
```

- 처음 들어오면 **아직 통과하지 않은 첫 레벨**이 자동 선택된다.
- 잠긴 레벨은 회색 + 자물쇠 아이콘이며 클릭할 수 없다.
- 통과한 레벨은 초록 체크로 표시되고, 다시 들어가 복습할 수 있다.

### 4-2. 레벨별 의미 (8개 과목 공통)

| 레벨 | 서버 상태 | 학습 포인트 | 통과 조건 |
|---|---|---|---|
| 하 (Low) | 방어 없음 | 취약점의 기본 원리 | 공격 성공 |
| 중 (Medium) | 단순한 방어(일부 문자·조건만 검사) | 그 방어가 왜 부족한가 | 공격 성공 |
| 상 (High) | 강화된 방어(금지 목록 확장 등) | 금지 목록 방식의 한계 | 공격 성공 |
| 안전 (Impossible) | 올바른 방어 코드 | 공격이 막히는 원리 | 1회 이상 시도 |

### 관련 파일

| 파일 | 역할 |
|---|---|
| `backend/app/progress.py` | 레벨 순서·잠금 판정·통과 기록 함수 추가 (`cleared_tiers`, `is_tier_unlocked`, `mark_tier_cleared`, `tier_states`) |
| `backend/app/courses.py` | `GET /courses/<slug>/practice/tiers` 추가, 실행·힌트 API에 잠금 검사 추가, 실행 응답에 `tierCleared`·`tiers` 추가 |
| `frontend/src/content/tierGuides.js` | 레벨 공통 의미(하·중·상·안전) 문구 |
| `frontend/src/views/ChapterDetailView.vue` | 라디오 버튼 → 레벨 스테퍼, 레벨 안내 카드, 통과 알림 |

## 5. 동작 원리 (레벨 잠금)

```
[실습 화면 열기]  GET /courses/<slug>/practice/tiers
      - task_progress 에서 tier_low / tier_medium ... 행 조회
      - 레벨별 { unlocked, cleared } 계산 → 스테퍼 표시
      ▼
[현재 레벨에서 실행]  POST /courses/<slug>/practice/run { difficulty, input }
      - 서버가 먼저 잠금 검사: 앞 레벨 미통과면 403
      - 실습 실행 → 성공 여부 판정
      - 하·중·상 성공  또는  안전 레벨 시도 → tier_<레벨> 기록(멱등)
      ▼
[응답]  { success, output, tierCleared, tiers }
      - 화면이 tiers 로 스테퍼를 즉시 갱신
      - "OO 레벨 통과! 이제 OO 레벨이 열렸습니다." 안내
```

잠금 판정 핵심 코드:

```python
TIER_ORDER = ("low", "medium", "high", "impossible")

def is_tier_unlocked(tier, cleared):
    """첫 레벨은 항상 열림, 그 외에는 바로 앞 레벨을 통과해야 열림"""
    index = TIER_ORDER.index(tier)
    return index == 0 or TIER_ORDER[index - 1] in cleared
```

### 왜 이렇게 했나

- **서버에서도 강제**: 화면에서 버튼만 막으면 개발자 도구로 요청을 직접 보내 건너뛸 수 있다. 보안 학습 플랫폼이므로 "클라이언트 검증만 믿지 않는다"는 원칙을 그대로 지켰다.
- **기존 테이블 재사용**: 진도율·관리자 집계는 `TASK_KEYS`(개념·실습·퀴즈)로만 필터링하므로, `tier_*` 키를 같은 테이블에 넣어도 진도율 계산에 섞이지 않는다. 마이그레이션 없이 바로 적용된다.
- **안전 레벨은 "시도"로 통과**: 안전 레벨은 공격이 성공하면 안 되는 단계다. 목표가 "막히는 것을 확인"이므로 1회 시도를 통과로 본다.
- **레벨 의미 고정**: 과목마다 레벨 설명이 제각각이면 다시 "섞인" 느낌이 난다. 하·중·상·안전이 모든 과목에서 같은 뜻을 갖도록 공통 문구로 통일했다.
- **보상·진도율은 그대로**: 미션의 "실습 성공"과 보상 지급 기준은 바꾸지 않았다. 레벨 구조만 정리해 다른 기능에 영향이 없게 했다.

---

## 6. 난이도(단계) 대신 — 레벨 상태별 표시

| 상태 | 표시 | 클릭 | 의미 |
|---|---|---|---|
| 진행 가능 | 번호(파란색) | 가능 | 지금 풀어야 할 레벨 |
| 통과 | 초록 체크 | 가능(복습) | 이미 통과한 레벨 |
| 잠김 | 회색 + 자물쇠 | 불가 | 앞 레벨을 먼저 통과해야 함 |

---

## 7. 핵심 정리

- 피드백("레벨이 섞여 있다")을 반영해, 실습 레벨을 **하 → 중 → 상 → 안전** 순서로만 진행하도록 바꿨다.
- 앞 레벨을 통과해야 다음 레벨이 열리며, 이 규칙은 **화면과 서버 모두**에서 지킨다.
- 레벨의 의미(방어 없음 → 단순 방어 → 강화 방어 → 올바른 방어)를 8개 과목에서 동일하게 보여준다.
- DB 구조 변경 없이 기존 `task_progress` 를 재사용했다.

---

## 8. 검증

- 백엔드 `progress.py` · `courses.py` 문법 검사 통과
- `GET /practice/tiers`: 처음 들어온 학생 기준 하만 `unlocked: true`, 나머지 잠김 확인
- 잠긴 레벨(중) 힌트 요청 → **403** "이전 레벨을 먼저 통과해야 이 레벨을 학습할 수 있습니다." 확인
- 실습 화면(Command Injection): 스테퍼·자물쇠·레벨 안내 카드 표시 확인, 하 레벨에서 정상 입력 실행 시 "실패"로 표시되고 잠금 유지 확인
- **확인 필요**: 하 레벨 공격 성공 → 중 레벨 열림 + 통과 안내 표시 (실제 공격 입력으로 직접 확인 권장)
- 참고: 이번 변경 전에 실습을 성공한 학생은 레벨 기록이 없으므로 하 레벨부터 다시 진행된다
