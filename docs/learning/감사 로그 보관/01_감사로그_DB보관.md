## 1. 요약

- 새 테이블 **`audit_logs`** 에 감사 기록을 저장한다. 서버 로그(`[AUDIT]`)도 그대로 남긴다(두 곳 기록).
- 기록 함수를 **`backend/app/audit.py` 의 `record_audit()` 하나로 통일**했다. (기존엔 `admin.py` · `profile.py` 에 따로 있었음)
- 기록은 **변경 작업과 같은 트랜잭션**에 들어간다 → "비밀번호는 바뀌었는데 기록은 없음" 같은 상황이 생기지 않는다.
- **회원이 삭제돼도 기록은 남는다**(외래키 없이 아이디를 기록 시점 값으로 저장).
- 개인정보 **값**(이메일 · 번호 · 비밀번호)은 저장하지 않는다. "이름 · 이메일 변경" 처럼 **항목 이름**만.
- 관리자 페이지에 **[감사 로그] 탭** 추가: 동작 필터 · 아이디 검색 · 50건씩 페이지.
- 새로 기록하는 동작 1개 추가: **비밀번호 찾기로 재설정**(본인 인증 후 변경).

---

## 2. 기록하는 동작

| action | 화면 이름 | 행위자 | 대상 | 상세 |
|---|---|---|---|---|
| `reset_password` | 임시 비밀번호 발급 | 관리자 | 학생 | - |
| `delete_user` | 회원 삭제 | 관리자 | 학생 | - |
| `change_own_password` | 관리자 비밀번호 변경 | 관리자 | - | - |
| `update_account` | 회원정보 변경 | 본인 | - | 바뀐 항목 이름 (예: 이름 · 이메일) |
| `change_password` | 비밀번호 변경 (마이페이지) | 본인 | - | - |
| `reset_password_self` | 비밀번호 찾기로 재설정 **(신규)** | 본인 | - | 이메일 인증 / 휴대폰 인증 |

실패한 요청(현재 비밀번호 틀림, 중복 409 등)은 변경이 없으므로 기록하지 않는다. (로그인 실패 기록은 점검표 #9 로 별도)

```

┌──────────────────────────────────────────────────────────────────────┐
│ [전체 동작 ▼] [아이디 검색 (행위자 · 대상)      ] [검색]        총 5건 │
│ 🛡 서버 로그와 별도로 DB 에 보관됩니다. 회원이 삭제돼도 기록은 남고 …   │
│ 일시                 행위자        동작              대상    상세     IP │
│ 2026-10-09 18:12:05  admin [관리자] [회원 삭제]       victim  -        … │
│ 2026-10-09 18:10:41  admin [관리자] [임시 비밀번호 발급] demo1 -       … │
│ 2026-10-09 17:58:13  demo1          [비밀번호 찾기로 재설정] - 이메일 인증 │
```

- 일시는 한국 시간(KST). 회원 삭제는 빨간 배지.
- 색은 모두 `var(--sq-*)` 토큰, 표 스타일은 회원관리 탭과 같다.

### 테이블 `audit_logs`

| 컬럼 | 설명 |
|---|---|
| `id` | PK |
| `actor_id` · `actor_username` · `actor_role` | 행위자 (FK 없음, 아이디는 기록 시점 값) |
| `action` | 동작 키 (위 표) |
| `target_id` · `target_username` | 대상 회원 (본인 작업이면 NULL) |
| `detail` | 바뀐 항목 이름 등 (개인정보 값 금지, 255자) |
| `ip` | 요청 IP (IPv6 까지 45자) |
| `created_at` | 기록 시각 (인덱스) |

인덱스: `created_at`, `(action, created_at)` — 최신순 조회 · 동작 필터용.

### API

| 메서드 · 경로 | 권한 | 쿼리 | 응답 |
|---|---|---|---|
| `GET /api/v1/admin/audit-logs` | 관리자 | `action`(선택, 목록에 있는 값만) · `q`(아이디 검색, 80자) · `page` | `{ total, page, pageSize: 50, actions: [...], items: [{ createdAt(KST), actor, actorRole, action, actionLabel, target, detail, ip }] }` |

학생 401/403, 알 수 없는 `action` 400.

## 5. 동작 원리

```
[변경 요청] ─▶ 검증 ─▶ 값 변경 ─▶ record_audit()  ─▶ db.session.commit()
                                   │ session.add(AuditLog)     (변경 + 기록 한 번에 저장)
                                   └ logger.warning("[AUDIT] …")
                실패(400/409) ─▶ rollback ─▶ 기록도 함께 취소
```

- **회원 삭제**: 회원 행을 지우기 **전에** `record_audit` 로 아이디를 기록 → 같은 commit 에서 삭제. `audit_logs` 는 회원 삭제 때 지우는 목록(`Enrollment` · `Reward` …)에 넣지 않았다.
- **IP**: `request.remote_addr` 사용. `X-Forwarded-For` 는 사용자가 마음대로 넣을 수 있는 헤더라 신뢰하지 않는다.

## 6. 테스트 결과

로컬에서 실제 Flask 앱 + SQLite(메모리) + 가짜 Redis 로 확인.

| 확인 | 결과 |
|---|---|
| 학생 회원정보 변경 → 기록 | ✅ `update_account` · `fields=name,email` |
| 학생 이메일 중복(409) | ✅ 기록 **안 됨** (rollback) |
| 학생 비밀번호 변경 | ✅ `change_password` |
| 학생이 감사 로그 API 호출 | ✅ 403 |
| 관리자 임시 비밀번호 · 회원 삭제 · 본인 비밀번호 변경 | ✅ 3건 기록, 대상 아이디 포함 |
| 삭제된 회원(victim) | 회원 행 없음, **감사 기록은 남음** ✅ |
| 비밀번호 찾기(이메일 인증) 후 재설정 | ✅ `reset_password_self` · `via=email` |
| 동작 필터 `delete_user` · 아이디 검색 `victim` | ✅ 각 1건 |
| 알 수 없는 동작 `action=drop` | ✅ 400 |
| 검색어 `' OR 1=1--` | ✅ 0건 (바인딩 처리로 SQL 로 해석 안 됨) |
| 관리자 화면 [감사 로그] 탭 (Nginx CSP 적용 상태) | ✅ 표시 정상, CSP 위반 0건 |
| 프론트엔드 `vite build` | ✅ |

### 직접 적용 · 확인하는 방법

새 테이블이 생기므로 **DB 마이그레이션**이 필요하다.

```bash
cd /mnt/d/study/Project/Final-Project
docker compose exec backend flask db upgrade     # audit_logs 테이블 생성
docker compose exec backend flask db current     # a1d17c0de001 (head) 이면 성공
```

1. 학생 계정으로 로그인 → 마이페이지에서 이름 변경
2. 관리자 계정으로 로그인 → [관리자] → [감사 로그] 탭 → 방금 기록 확인
3. (선택) 서버 로그도 함께 남는지: `docker compose logs backend | grep AUDIT`

실제 확인 결과 (2026-10-09, Docker):

```
$ docker compose exec backend flask db upgrade
INFO  [alembic.runtime.migration] Running upgrade 752399d75810 -> a1d17c0de001, add audit_logs (감사 로그 DB 보관)

$ docker compose logs backend | grep AUDIT
backend-1  | [2026-10-09 09:13:49,001] WARNING in audit: [AUDIT] actor_id=2 action=update_account target_user_id=- fields=name ip=172.24.0.6
```

> 서버 로그 시각(09:13)은 **UTC** 기준이다. 관리자 [감사 로그] 탭은 한국 시간(KST, 18:13)으로 바꿔 보여 준다.
> IP `172.24.0.6` 은 Docker 내부망에서 본 Nginx 컨테이너 주소다(요청이 Nginx 를 거쳐 들어오기 때문). 실제 접속자 IP 를 남기려면 Nginx 의 `X-Real-IP` 를 백엔드가 신뢰하도록 설정해야 하며, 이는 운영 배포 때 함께 할 작업으로 남긴다.
