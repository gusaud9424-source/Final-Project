# 03. 로그인 실패 기록

> 대상: 웹 보안을 처음 배우는 입문자
> 목표: 로그인 실패를 감사 로그에 남겨 무작위 대입(브루트포스) · 계정 탈취 시도를 관리자가 확인할 수 있게 한다.
> 작성: 2026-10-09 · 오현명
> 관련: 기능 점검표 #9, `01_감사로그_DB보관.md`(같은 `audit_logs` 테이블 사용 — 마이그레이션 없음)

---

## 1. 요약

- 로그인이 실패하면 `audit_logs` 에 **`login_failed`** 1건을 남긴다. 실패 사유 3가지를 구분한다.
- 학생 화면의 오류 문구는 **그대로**("아이디 또는 비밀번호가 올바르지 않습니다") — 사유 구분은 관리자 기록에만.
- **없는 아이디도 bcrypt 비교를 한 번 수행**해 응답 시간을 맞췄다(시간 차이로 가입 여부를 알아내는 것 방지).
- 관리자 [감사 로그] 탭에 **"최근 24시간 로그인 실패 N건"** 표시줄 추가. 1건 이상이면 빨간색, 누르면 로그인 실패만 필터.
- 기존 Rate Limit(분당 10회/IP)은 그대로. 이제 **"막는 장치" + "기록하는 장치"** 가 함께 있다.

---

## 2. 기록 내용

| 실패 사유 (`detail`) | 화면 표시 | 행위자(`actor_*`) |
|---|---|---|
| `reason=unknown_user` | 없는 아이디 | 입력한 아이디(최대 30자), 계정 ID 없음 |
| `reason=wrong_password` | 비밀번호 틀림 | 실제 계정 (ID · 아이디 · 역할) |
| `reason=role_mismatch` | 역할 불일치(학생/관리자) | 실제 계정 |

- **비밀번호는 어떤 경우에도 저장하지 않는다.**
- 입력한 아이디를 30자까지만 저장하는 이유: 사용자가 아이디 칸에 비밀번호를 잘못 입력하는 경우가 있어, 긴 값을 그대로 남기지 않는다.
- 성공한 로그인은 기록하지 않는다(실패 감지가 목적, 기록량 절약).

## 3. 화면

```
┌───────────────────────────────────────────────────────────────┐
│ 🛡 최근 24시간 로그인 실패 3건                   로그인 실패만 보기 │ ← 1건 이상이면 빨간 배경
└───────────────────────────────────────────────────────────────┘
 일시                 행위자                       동작        상세
 2026-10-09 18:30:11  <script>alert(1)</script>    [로그인 실패] 없는 아이디   ← 글자로만 표시, 실행 안 됨
 2026-10-09 18:29:58  demo1                        [로그인 실패] 비밀번호 틀림
 2026-10-09 18:29:40  demo1                        [로그인 실패] 역할 불일치(학생/관리자)
```

- 같은 아이디로 짧은 시간에 실패가 몰리면 → 그 계정을 노리는 대입 시도.
- 여러 아이디가 같은 IP 에서 실패하면 → 아이디 목록을 돌리는 시도(크리덴셜 스터핑).

## 4. 관련 파일

| 파일 | 변경 |
|---|---|
| `backend/app/audit.py` | `login_failed` 라벨, `record_login_failure()` 추가 |
| `backend/app/auth.py` | 로그인 실패 3곳에서 기록, 없는 아이디 더미 bcrypt 비교, 입력값 문자열 변환 |

| `frontend/src/components/admin/AuditLog.vue` | 24시간 실패 표시줄 · 실패 사유 한국어 · 로그인 실패 빨간 배지 |

## 5. 동작 원리

```
POST /auth/login
  ├─ Rate Limit (분당 10회/IP) 초과 → 429  (기록 안 함: 요청 자체가 막힘)
  ├─ 아이디 없음   → 더미 bcrypt 비교 → record_login_failure(unknown_user)  → 401
  ├─ 비밀번호 틀림 →                   record_login_failure(wrong_password) → 401
  ├─ 역할 불일치   →                   record_login_failure(role_mismatch)  → 401
  └─ 성공 → 세션 발급 (기록 안 함)
```

- 로그인 실패는 바꾸는 데이터가 없으므로 `record_login_failure()` 안에서 바로 commit 한다.
- 기록 저장이 실패해도 로그인 응답(401)은 그대로 나간다(서버 로그에 오류만 남김).

### 왜 더미 bcrypt 비교를 하나 (타이밍 공격)

| | 수정 전 | 수정 후 |
|---|---|---|
| 있는 아이디 + 틀린 비밀번호 | bcrypt 비교(약 0.2초) | 같음 |
| 없는 아이디 | **바로 응답(수 ms)** | 더미 해시와 bcrypt 비교(약 0.2초) |

수정 전에는 응답 속도만 재도 "이 아이디는 가입돼 있다"를 알 수 있었다. 문구를 똑같이 맞춰도 **시간이 정보를 흘린다.** 더미 해시는 실제 계정과 같은 cost(12)로 만들어 시간이 비슷하다.

## 6. 테스트 결과

로컬 실제 Flask 앱 + SQLite(메모리) + 가짜 Redis.

| 확인 | 결과 |
|---|---|
| 없는 아이디 / 비밀번호 틀림 / 역할 불일치 | 401, 각각 `unknown_user` · `wrong_password` · `role_mismatch` 기록 ✅ |
| 정상 로그인 | 200, 기록 없음 ✅ |
| 아이디에 `<script>`+긴 문자열 | 401, 30자까지만 저장 ✅ / 화면에는 글자로만 표시(alert 없음) ✅ |
| 아이디에 배열 · 비밀번호에 숫자 등 이상한 값 | 401 (서버 오류 없음) ✅ |
| 없는 아이디 응답 시간 | 약 164ms (bcrypt 비교 수행) ✅ |
| 관리자 감사 로그 `action=login_failed` · `loginFailures24h` | 정상 ✅ |
| 관리자 탭 화면 (Nginx CSP 적용) | 표시줄 · 사유 · 배지 정상, CSP 위반 0건 ✅ |
| 프론트엔드 `vite build` | ✅ |

### 직접 확인하는 방법

DB 변경이 없어 `flask db upgrade` 는 필요 없다.

> ⚠️ **같은 브라우저 창 두 개로 관리자 · 학생을 동시에 로그인할 수 없다.**
> 같은 브라우저는 창이 여러 개여도 **쿠키를 하나로 공유**한다. SecuQuest 는 로그인 상태를 세션 쿠키 하나로 기억하므로,
> 한 창에서 학생으로 로그인하면 다른 창의 관리자 세션이 덮어써진다(새로고침하면 둘 다 학생). 버그가 아니라 세션 쿠키의 정상 동작이다.
>
> 두 계정을 동시에 쓰려면 쿠키 저장소를 나눈다:
>
> | 방법 | 관리자 | 학생 |
> |---|---|---|
> | **시크릿 창 (추천)** | 일반 창 `http://localhost:8090` | 시크릿 창(Chrome `Ctrl+Shift+N` / Edge `Ctrl+Shift+P`) `http://localhost:8090` |
> | 주소 다르게 | `http://localhost:8090` | `http://127.0.0.1:8090` (브라우저가 다른 사이트로 보고 쿠키를 따로 저장) |
> | 브라우저 다르게 | Chrome | Edge |

1. **일반 창**: 관리자 로그인 → [관리자] → [감사 로그] 열어 두기
2. **시크릿 창**: 틀린 비밀번호로 1회, 없는 아이디로 1회 로그인 시도
3. **일반 창**: [감사 로그] 탭 다시 클릭 → 빨간 "최근 24시간 로그인 실패 2건" → [로그인 실패만 보기]
4. (선택) `docker compose logs backend | grep login_failed`

## 7. 남은 한계 · 다음 작업

- **자동 잠금 없음**: 실패가 많아도 계정을 잠그지 않는다(잠금은 반대로 남의 계정을 일부러 잠그는 공격에 쓰일 수 있어 정책이 필요). 지금은 IP 별 Rate Limit + 기록.
- **알림 없음**: 관리자가 탭을 열어야 보인다. 운영이면 실패 급증 시 메일 알림.
- **IP 가 Nginx 내부 주소**로 기록되는 한계는 `01` 문서와 같다(운영 배포 때 `X-Real-IP` 신뢰 설정).
