# 02. 출석 체크 개념 설명 (하루 1회 · 14일 판 · 포인트 즉시 적립)

## 1. 요약

- 학생이 대시보드에 들어오면 **14칸(2줄 × 7칸) 출석판**이 뜬다. 하루에 한 번 버튼을 누르면 **포인트를 랜덤으로** 받는다.
- 보통 날은 **50~200P**, 7·14일차는 보너스로 **300~500P**.
- 출석 포인트는 보물상자를 거치지 않고 **버튼을 누르는 순간 바로 포인트 장부(PointLedger)에 기록**된다.
- "하루 한 번"은 기록에 붙이는 이름표 **`att:<오늘 날짜>`** 와 DB의 **UNIQUE 제약**으로 지킨다. 같은 날 두 번 눌러도, 동시에 두 번 요청이 와도 한 번만 적립된다.
- "오늘"은 서버 시간이 아니라 **한국 시간(KST)** 기준으로 정한다.
- 출석 기록을 위한 새 테이블은 만들지 않았다. 포인트 장부 한 줄이 곧 출석 도장이다.

## 2. 개념 설명 (비유)

### 2-1. 전체 그림: 카페 도장판 + 통장

```
 [학생]                 [화면]                      [서버]                        [DB]
 대시보드 접속 ──▶ GET /attendance ──────────▶ 출석 기록 조회 ─────────────▶ point_ledger
                  (오늘 받을 수 있나?)          몇 일차까지 받았나?               source="attendance" 줄들
                        │                     오늘 받았나?
                        ▼
                  출석판 모달 자동 표시
 버튼 클릭 ─────▶ POST /attendance/claim ────▶ 오늘 이미 받았으면 409 거절
                                               아니면 랜덤 포인트 계산 ─────▶ 한 줄 추가
                                                                              ref="att:2026-10-06"
                        ◀──────────────────── 적립 일차 · 금액 · 보유 포인트
                  헤더 보유 포인트 즉시 갱신
```

- **도장판(출석판)** 은 화면에 보이는 그림일 뿐이다.
- **진짜 도장(기록)** 은 포인트 장부의 한 줄이다. 이 줄의 개수가 곧 "며칠 출석했는지"다.
- 비유: 카페가 도장판 종이를 따로 보관하지 않고, **포인트 적립 영수증 묶음**을 세어서 도장 개수를 판단하는 방식이다.

### 2-2. "하루 한 번"을 지키는 두 겹의 확인

1. **먼저 확인**: 서버가 오늘 날짜 이름표(`att:2026-10-06`)가 이미 있는지 찾아보고, 있으면 409로 거절한다.
2. **마지막 안전장치**: 두 요청이 거의 동시에 와서 둘 다 "아직 없음"으로 통과해도, DB가 **같은 이름표의 두 번째 줄 저장을 거부**한다(UNIQUE 제약). 서버는 이 거부를 받아 "오늘은 이미 출석했습니다"로 응답한다.

비유: 입구 직원이 명단을 확인하고(1), 그래도 같은 사람이 동시에 두 문으로 들어오면 자리 배정 시스템이 같은 좌석을 두 번 주지 않는다(2).

## 3. 용어 설명

| 용어 | 쉬운 뜻 |
|---|---|
| 출석판 | 14칸 그리드 화면. 날마다 한 칸씩 채워진다 |
| 포인트(P) | 모아 두는 보상 점수. 헤더의 "보유 포인트" |
| PointLedger(포인트 장부) | 포인트가 생길 때마다 한 줄씩 쌓는 DB 테이블 `point_ledger` |
| source | 포인트가 생긴 이유. 출석은 `"attendance"` |
| ref | 중복 방지 이름표. 출석은 `att:<KST 날짜>` (예: `att:2026-10-06`) |
| UNIQUE 제약 | "이 값 조합은 한 줄만 허용"하는 DB 규칙. 여기서는 `(user_id, source, ref)` |
| IntegrityError | UNIQUE 같은 DB 규칙을 어겨 저장이 거부될 때 나는 오류 |
| 롤백(rollback) | 실패한 저장 작업을 없던 일로 되돌리기 |
| 멱등 | 여러 번 요청해도 결과가 한 번 한 것과 같음 |
| 동시 요청(경쟁 상태) | 거의 같은 순간에 같은 요청이 두 번 와서 서로 결과를 덮어쓸 수 있는 상황 |
| KST | 한국 표준시(Asia/Seoul). "오늘" 날짜의 기준 |
| UTC | 세계 기준 시간. 한국보다 9시간 느리다 |
| ZoneInfo | 파이썬에서 시간대를 지정하는 도구 |
| 409 Conflict | "이미 처리된 요청이라 충돌한다"는 응답 번호 (오늘 이미 출석 / 14일 완료) |
| 401 | 로그인이 필요하다는 응답 번호 |
| Rate Limit | 같은 사람이 짧은 시간에 너무 많이 요청하지 못하게 막는 것 (`20 per minute`) |
| 모달 | 화면 위에 떠서 다른 곳을 가리는 작은 창 |

## 4. 구조와 코드

### 4-1. 설정값

```python
# backend/app/attendance.py
BOARD_DAYS = 14                  # 출석판 칸 수
BONUS_DAYS = {7, 14}             # 보너스 날
NORMAL_RANGE = (50, 200)         # 보통 날 포인트 범위
BONUS_RANGE = (300, 500)         # 보너스 날 포인트 범위
_KST = ZoneInfo("Asia/Seoul")
```

| 값 | 의미 | 바꾸면 |
|---|---|---|
| `BOARD_DAYS` | 출석판 길이 | 칸 수와 완료 기준이 함께 바뀜 |
| `BONUS_DAYS` | 보너스 칸 | 화면의 노란 칸 위치도 서버 응답대로 바뀜 |
| `*_RANGE` | 랜덤 포인트 범위 | 지급 금액 범위 조정 |

### 4-2. "오늘"을 한국 날짜로 정하기

```python
def _today():
    return datetime.now(_KST).date().isoformat()     # 예: "2026-10-06"
```

- 서버(Docker)는 보통 UTC로 돌아간다. 한국 시간 새벽 0~9시는 UTC로는 **전날**이다.
- UTC 기준으로 날짜를 잡으면 한국에서 오전 8시에 출석했을 때 "어제"로 기록되는 일이 생긴다.
- 그래서 **한국 시간으로 날짜 문자열을 직접 만들어** 이름표에 쓴다. 한국 자정이 지나면 새 날이 시작된다.

### 4-3. 출석판 상태 계산 (`_board_state`)

```python
rows = _rows(user_id)                                  # 출석 줄들을 시간순으로
claimed_today = any(r.ref == f"att:{today}" for r in rows)
completed = min(len(rows), BOARD_DAYS)                 # 받은 일차 수 (최대 14)
next_day = completed + 1
can_claim = completed < BOARD_DAYS and not claimed_today

for d in range(1, BOARD_DAYS + 1):
    if d <= completed:                state = "claimed"      # 받은 칸 (+금액 표시)
    elif d == next_day and can_claim: state = "claimable"    # 오늘 받을 칸
    else:                             state = "locked"       # 아직 순서 아님
```

- **며칠차는 "줄 개수"로 센다.** 3일 연속이 아니어도, 출석한 날이 3번이면 3일차까지 채워진다. (연속 출석 개념은 없다)
- 칸 상태와 금액은 서버가 계산해 내려주고, 화면은 그대로 그린다.

| 칸 상태 | 조건 | 화면 |
|---|---|---|
| `claimed` | 이미 받은 일차 | 초록 · +N P |
| `claimable` | 다음 일차이고 오늘 아직 안 받음 | 강조 · 버튼 활성 |
| `locked` | 아직 순서가 아님 | 흐림 |

### 4-4. 출석하기 (`POST /attendance/claim`)

```python
@bp.post("/claim")
@limiter.limit("20 per minute")                       # ① 과도한 반복 요청 제한
def claim():
    ...
    if completed >= BOARD_DAYS:
        return jsonify(message="14일 출석을 모두 완료했습니다."), 409   # ② 판 완료
    if any(r.ref == f"att:{today}" for r in rows):
        return jsonify(message="오늘은 이미 출석했습니다."), 409        # ③ 오늘 이미 출석

    day = completed + 1
    amount = _roll(day)                                # ④ 금액은 서버가 랜덤 결정
    db.session.add(PointLedger(user_id=user.id, source="attendance",
                               ref=f"att:{today}", amount=amount, reason=f"출석 {day}일차"))
    try:
        db.session.commit()
    except IntegrityError:                             # ⑤ 동시 요청으로 같은 이름표 → DB가 거부
        db.session.rollback()
        return jsonify(message="오늘은 이미 출석했습니다."), 409
```

| 번호 | 의미 | 없으면 생기는 일 |
|---|---|---|
| ① Rate Limit | 1분에 20번까지만 | 자동 프로그램으로 요청을 퍼부어 서버에 부담 |
| ② 14일 완료 확인 | 판을 다 채우면 더 못 받음 | 15일차 이후에도 계속 적립 |
| ③ 오늘 출석 확인 | 같은 날 두 번째 요청 거절 | 하루에 여러 번 포인트 획득 |
| ④ 서버가 금액 결정 | 화면은 금액을 보내지 않음 | 화면을 조작해 큰 금액을 보낼 수 있음 |
| ⑤ UNIQUE + 롤백 | 동시에 두 번 와도 한 번만 저장 | 버튼을 빠르게 두 번 누르면 두 번 적립 |

### 4-5. 왜 보물상자를 거치지 않나

- 다른 보상은 "교환권(Reward) → 클릭 수령 → 장부 입금" 순서다(`보상 UI 정리/09` 참고).
- 출석은 **버튼을 누르는 행동 자체가 수령**이라 교환권 단계가 필요 없다. 그래서 바로 장부에 기록한다.
- 장부의 `source="attendance"` 줄은 관리자 화면에서 **출석 횟수 · 마지막 활동 시각** 계산에도 쓰인다.

```
10월 6일 08:00 (KST)  대시보드 접속 → 출석판 자동 표시 (1일차 claimable)
                      버튼 클릭 → att:2026-10-06 기록, +132P → 헤더 포인트 갱신
10월 6일 21:00        다시 버튼 → 409 "오늘은 이미 출석했습니다."
10월 7일 00:05        한국 날짜가 바뀜 → 2일차 claimable
10월 9일              (7·8일은 안 들어옴) → 3일차 claimable (연속이 아니어도 다음 칸)
…7번째 출석           7일차 보너스 → 300~500P
…14번째 출석          14일차 보너스 → 판 완료, 이후 409 "14일 출석을 모두 완료했습니다."
```

## 6. 주의점과 한계

- **연속 출석이 아니라 "출석한 날 수"** 기준이다. 빠진 날이 있어도 다음 칸으로 이어진다.
- **14일을 채우면 끝**이다. 판을 새로 시작하는 기능은 아직 없다.
- 출석 포인트는 **포인트만** 준다(경험치 없음). 그래서 출석으로는 레벨이 오르지 않는다.
- 출석 기록은 수강신청 초기화와 **관계없다**(과목이 아니라 계정 단위 기록이라 유지된다).

---

## 7. 핵심 정리

- 출석은 하루 1회, 14칸, 보통 50~200P · 7·14일차 300~500P를 **버튼 클릭 즉시** 포인트 장부에 적립한다.
- "하루 한 번"은 **한국 날짜 이름표(`att:<날짜>`) + 사전 확인(409) + DB UNIQUE 제약** 세 겹으로 지킨다.
- 며칠차는 장부의 출석 줄 개수로 센다. 별도 출석 테이블이 없다.
- 발표용 한 문장: **"출석 기록을 포인트 장부 한 줄로 남기고, 한국 날짜 이름표와 DB 고유 제약으로 동시에 눌러도 하루 한 번만 적립되게 했다."**
