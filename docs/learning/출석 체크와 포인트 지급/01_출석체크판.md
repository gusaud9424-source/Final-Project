# 01. 로그인 출석 체크판 (포인트 지급)

> 대상: 웹 보안을 처음 배우는 입문자
> 목표: "로그인하면 뜨는 출석판에서 하루 한 번 포인트를 받는" 기능이 프런트·백엔드·DB에서 어떻게 맞물려 동작하는지 이해한다.
> 작성: 2026-10-03 · 오현명

---

## 1. 한 줄 요약

학습자가 접속하면 14일 출석판이 뜨고, **하루에 한 번** 버튼을 눌러 **랜덤 포인트**를 적립받는 기능. 7·14일차는 보너스로 더 많은 포인트를 준다.

---

## 2. 개념 설명 (비유)

동네 카페의 **출석 도장판**과 같다.

- 하루에 한 번 방문하면 칸에 도장을 찍어 준다(출석).
- 도장을 찍을 때마다 쿠폰(=포인트)을 주는데, 그날그날 받는 양이 다르다(랜덤).
- 7번째·14번째 칸은 "특별 칸"이라 더 큰 보상을 준다(보너스).
- 같은 날 두 번 와도 도장은 하루 한 번만 찍힌다(하루 1회 제한).

웹에서는 도장판이 **출석 모달**, 도장 기록은 **서버의 포인트 장부(PointLedger)** 에 남는 한 줄이다.

---

## 3. 용어 설명

| 용어 | 뜻 |
|---|---|
| 출석 체크판 | 14일(2줄×7칸) 그리드. 날마다 한 칸씩 채워진다 |
| 포인트(Point) | 학습 보상 재화. 헤더의 "보유 포인트"에 합산 표시 |
| PointLedger | 포인트 적립 내역을 한 줄씩 쌓는 서버 장부(테이블) |
| source | 포인트가 생긴 출처 구분값. 출석은 `"attendance"` |
| ref | 중복 방지 키. 출석은 `att:<날짜>` 로 하루 1회를 강제 |
| 멱등(idempotent) | 같은 요청을 여러 번 보내도 결과가 한 번만 반영되는 성질 |
| KST | 한국 표준시(Asia/Seoul). "오늘"의 기준 날짜 |
| 보너스 데이 | 7·14일차. 더 큰 랜덤 포인트 범위 적용 |

---

## 4. 화면 & 동작

### 화면

```
┌───────────────────────────────────────────────┐
│ 출석 체크                                 ✕    │
│ 매일 접속하고 출석하면 포인트를 받아요.  보유 149P │
│ ┌──┬──┬──┬──┬──┬──┬──┐                        │
│ │1 │2 │3 │4 │5 │6 │7★│   ← 1줄차 (7★ 보너스)   │
│ ├──┼──┼──┼──┼──┼──┼──┤                        │
│ │8 │9 │10│11│12│13│14★│  ← 2줄차 (14★ 보너스)  │
│ └──┴──┴──┴──┴──┴──┴──┘                        │
│        [ 오늘 출석하고 포인트 받기 ]            │
│ 🎉 1일차 출석 완료! 포인트 +149P 적립           │
└───────────────────────────────────────────────┘
```

- **접속 시 자동 표시**: 대시보드를 열 때 "오늘 받을 수 있으면" 모달이 자동으로 뜬다. "출석 체크" 버튼으로 다시 열 수도 있다.
- 각 칸 상태: **완료**(초록·+N P 표시) / **오늘 가능**(강조·클릭 가능) / **잠김**(흐림).
- 7·14일차는 노란색 보너스 칸.

### 관련 파일

| 파일 | 역할 |
|---|---|
| `backend/app/attendance.py` | 출석 조회/적립 API, 랜덤 포인트·하루 1회·보너스 로직 |
| `backend/app/models.py` (`PointLedger`) | 포인트 적립 장부(출석 기록도 여기에) |
| `backend/app/__init__.py` | `attendance` 블루프린트 등록 |
| `frontend/src/components/dashboard/AttendanceBoard.vue` | 14일 출석판 모달 UI |
| `frontend/src/views/DashboardView.vue` | 접속 시 자동 열기 + "출석 체크" 버튼 |

## 5. 동작 원리 (적립 흐름)

```
[1] 대시보드 접속
      │  GET /api/v1/attendance
      ▼
[2] 서버: 내 출석 기록(PointLedger source=attendance) 조회
      - 몇 일차까지 받았는지(completed), 오늘 받았는지(claimedToday) 계산
      - canClaimToday = (14일 미만) AND (오늘 아직 안 받음)
      ▼
[3] 프런트: canClaimToday 면 출석 모달 자동 표시
      │  [오늘 출석하고 포인트 받기] 클릭
      │  POST /api/v1/attendance/claim
      ▼
[4] 서버:
      - 오늘(KST) 이미 받았으면 409 거부
      - day = 다음 일차, 랜덤 포인트 계산(보너스면 큰 범위)
      - PointLedger 에 한 줄 추가 (source=attendance, ref=att:<오늘날짜>)
      ▼
[5] 응답: 적립 일차·금액·보유 포인트 → 헤더 포인트 즉시 갱신
```

### 왜 이렇게 설계했나

- **별도 테이블을 만들지 않았다.** 출석도 "포인트가 생긴 사건"이므로 기존 포인트 장부(`PointLedger`)에 `source="attendance"` 한 줄로 기록한다. DB 마이그레이션 없이 바로 동작한다.
- **하루 1회 보장**: 적립 줄의 `ref` 를 `att:<오늘 날짜(KST)>` 로 둔다. DB의 `UNIQUE(user, source, ref)` 제약 덕분에 같은 날 두 번 적립이 **불가능**하다(동시 요청도 안전). 날짜는 서버 시간대가 아니라 한국 날짜 문자열로 직접 계산해 시차 문제를 피한다.
- **며칠차인지**: 출석 줄을 시간순으로 세어 N일차를 매긴다(1~14).
- **랜덤·보너스**: 일반 날은 50~200P, 7·14일차는 300~500P 범위에서 무작위.

---

## 6. 난이도(단계) 대신 — 상태별 처리

이 기능은 공격/방어 실습이 아니라 보상 기능이므로, "난이도" 대신 **칸 상태**로 정리한다.

| 상태 | 조건 | 화면 | 적립 |
|---|---|---|---|
| 완료(claimed) | 이미 받은 일차 | 초록·+N P | 완료 |
| 오늘 가능(claimable) | 다음 일차 & 오늘 미수령 | 강조·버튼 활성 | 클릭 시 적립 |
| 잠김(locked) | 아직 순서 아님 | 흐림 | 불가 |
| 완료(14일) | 14일 모두 받음 | 버튼 비활성 | 종료 |

---

## 7. 핵심 정리

- 출석 체크판은 **하루 1회 랜덤 포인트**를 주는 보상 기능이며, 7·14일차는 보너스다.
- 포인트만 지급한다(경험치·아이템 없음) — 요청 사양 반영.
- 기록은 **PointLedger**에 `source="attendance"`, `ref="att:<KST 날짜>"` 한 줄로 남고, 이 `ref`의 UNIQUE 제약이 **하루 1회**를 보장한다.
- 프런트는 접속 시 받을 수 있으면 모달을 자동으로 띄우고, 적립 후 헤더의 보유 포인트를 즉시 갱신한다.
