## 1. 발견 · 처리 결과

| # | 문제 | 영향 | 처리 |
|---|---|---|---|
| 1 | `.env.example` 그대로 복사 시 빈 `MAIL_PORT=` 로 서버가 뜨지 않음. 빈 `SECRET_KEY=` 가 루트 `.env` 값을 덮어써 세션이 깨질 수 있음 | 클론 직후 실행 불가 | 빈 환경변수는 기본값 사용 (`config.py`) — 커밋 `fix(setup)` |
| 2 | 시드 비밀번호가 비어 있으면 학생 계정이 로그인 불가인 무작위 비밀번호로 생성, 이메일 · 번호 값이 없으면 시드 중단 | 시연 계정 로그인 불가 | `seed.py` 수정 + 시연용 기본 비밀번호(`.env.example`, 로컬 전용) |
| 3 | 1회차 개념 확인 문항이 8과목 모두 비어 있음 | 1회차 완료 불가 | 전용 문항이 없으면 3회차 퀴즈 문항에서 5개 출제 |
| 4 | SQL Injection · File Upload 중(Medium) 레벨은 DevTools · 프록시로 요청을 바꿔야 함 | 시연 중 막힐 수 있음 | **의도된 설계로 유지** (클라이언트 측 검증의 한계 학습). README 에 안내 추가 |
| 5 | (확인 결과 문제 아님) 긴 페이지 하단 배경이 흰색으로 보임 | - | 전체 페이지 스크린샷에서만 생기는 현상. 실제 스크롤은 정상 |
| 6 | Blind SQLi 중 레벨 힌트가 "드롭다운 · DevTools" 라고 안내하지만 실제 화면은 입력칸 | 학습자 혼동 | 힌트 문구를 화면에 맞게 수정 |
| 7 | 관리자 학생 상세 "단계 32/32" 문구가 진도율 기준 변경 전 표현 | 표기 불일치 | "실습 레벨 32/32" 로 수정 |

함께 반영한 개선: 진도율을 **실습 레벨 통과 기준(전체 8과목 × 4 = 32)** 으로 변경 (`05_진도율_실습레벨_기준변경.md`).

### 점검용 관리 명령 (레벨 통과 처리)

화면만으로 진행할 수 없는 레벨을 점검할 때 사용. 보상은 지급되지 않고 진도에만 반영된다.

```bash
docker compose exec backend python -c "
from app import create_app
from app.models import User, Course
from app.progress import mark_tier_cleared
app = create_app()
with app.app_context():
    u = User.query.filter_by(username='아이디').first()
    c = Course.query.filter_by(slug='과목-slug').first()
    mark_tier_cleared(u.id, c.id, 'medium')   # low / medium / high / impossible
"
```

> 같은 브라우저에서 학생 · 관리자를 동시에 쓰면 로그인 쿠키가 덮어써진다 → 한쪽은 시크릿 창 사용.
