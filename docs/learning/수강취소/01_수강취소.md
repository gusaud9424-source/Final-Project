# 01. 수강취소 버튼

> 대상: 웹 보안을 처음 배우는 입문자
> 목표: "수강 중인 과목을 취소하는" 기능이 프런트·백엔드·DB에서 어떻게 맞물려 동작하는지 이해한다.
> 작성: 2026-10-03 · 오현명

---

## 1. 한 줄 요약

수강신청 화면에서 **수강 중인 과목에만** "수강취소" 버튼이 보이고, 확인 후 누르면 수강 목록에서 빠진다. **학습 진도는 지워지지 않아** 다시 수강하면 이어서 진행된다.

---

## 2. 개념 설명 (비유)

헬스장 **회원권 해지**와 같다.

- 회원권을 해지하면 출입 명단(수강 목록)에서 이름이 빠진다.
- 출입 명단에 붙어 있던 출입 기록(출석 세션)도 함께 정리한다.
- 하지만 개인 운동 기록 노트(실습·퀴즈 진도, 포인트)는 내 것이라 그대로 남는다.
- 나중에 다시 등록하면 예전 기록을 보며 이어서 운동할 수 있다(재수강 시 이어하기).

웹에서는 출입 명단이 **`enrollments` 테이블의 한 줄**, 해지 요청이 **`DELETE` API 호출**이다.

---

## 3. 용어 설명

| 용어 | 뜻 |
|---|---|
| Enrollment | "누가 어떤 과목을 수강 중인가"를 기록하는 테이블 한 줄 (`user_id`, `course_id`) |
| AttendanceSession | 수강(Enrollment)에 딸린 출석 세션 기록. `enrollment_id` 외래키로 연결 |
| 외래키(FK) | 다른 테이블의 행을 가리키는 열. 부모 행을 지우기 전 자식 행을 먼저 정리해야 한다 |
| course_slug | 과목을 URL에서 구분하는 문자열 (예: `csrf`, `xss-dom`) |
| DELETE | HTTP 메서드. 서버의 자원(여기서는 수강 정보)을 삭제하라는 요청 |
| 204 No Content | "삭제 성공, 돌려줄 본문 없음" 응답 코드 |
| CSRF 토큰 | 다른 사이트가 몰래 요청을 보내지 못하게 막는 값. 모든 비-GET 요청 헤더(`X-CSRFToken`)에 자동 첨부 |

## 4. 화면 & 동작

### 화면

```
┌──────────────────────────────────────────────────────────┐
│ [초급] Command Injection                 ⌄  [이어하기] [수강취소] │  ← 수강 중
│ [중급] File Upload                       ⌄  [수강]             │  ← 미수강
└──────────────────────────────────────────────────────────┘
          │ [수강취소] 클릭
          ▼
  ┌──────────────────────────────────────────┐
  │ 'Command Injection' 수강을 취소할까요?      │
  │ 학습 진도는 보존되어 다시 수강하면           │
  │ 이어서 진행됩니다.          [취소] [확인]   │
  └──────────────────────────────────────────┘
```

- **수강 중인 과목만** 버튼이 보인다. 미수강 과목에는 "수강" 버튼만 있다.
- 확인 후 성공하면 버튼이 즉시 "수강"으로 바뀌고, 상단 "수강 중 N/8" 숫자도 줄어든다.
- 처리 중에는 두 버튼이 비활성화되어 중복 클릭을 막는다.
- 버튼 스타일은 흰 배경 + 테두리(보조 버튼), 마우스를 올리면 경고색으로 바뀐다. 색은 모두 `var(--sq-*)` 토큰만 사용했다.

### 관련 파일

| 파일 | 역할 |
|---|---|
| `backend/app/enrollments.py` | `DELETE /api/v1/enrollments/<course_slug>` 수강취소 API |
| `backend/app/models.py` (`Enrollment`, `AttendanceSession`) | 수강 정보와 그에 딸린 출석 세션 테이블 (변경 없음) |
| `frontend/src/stores/enroll.js` | `cancel(id)` 함수 추가 — API 호출 후 `enrolled=false` |
| `frontend/src/views/EnrollView.vue` | "수강취소" 버튼, 확인창, `handleCancel()` |

## 5. 동작 원리 (취소 흐름)

```
[1] 수강신청 화면에서 [수강취소] 클릭
      │  확인창(window.confirm) → 확인
      ▼
[2] 프런트: enrollStore.cancel(slug)
      │  DELETE /api/v1/enrollments/<slug>   (X-CSRFToken 헤더 자동 첨부)
      ▼
[3] 서버:
      - 로그인 안 했으면 401
      - 없는 과목이면 404
      - 내가 수강 중이 아니면 404
      - AttendanceSession(해당 수강의 출석 세션) 먼저 삭제
      - Enrollment 삭제 → commit
      ▼
[4] 응답 204 → 프런트: item.enrolled = false
      → 버튼 "수강"으로 변경, "수강 중 N/8" 감소
```

### 왜 이렇게 설계했나

- **자식 행 먼저 삭제**: `attendance_sessions.enrollment_id` 가 `enrollments.id` 를 외래키로 가리킨다. 부모(Enrollment)를 먼저 지우면 FK 제약 위반이 나므로, 출석 세션을 먼저 지운 뒤 수강 정보를 지운다.
- **진도는 보존**: 실습·퀴즈 진도(`task_progress`), 보상(`rewards`), 포인트·경험치 장부는 `enrollment_id` 가 아니라 `user_id` + 과목 기준으로 저장된다. 그래서 수강취소가 이 기록을 건드리지 않고, 재수강하면 그대로 "이어하기"가 된다. 실수로 취소해도 손해가 없도록 한 선택이다.
- **URL에 slug 사용**: 수강신청(`POST`)이 `course_slug` 로 동작하므로 취소도 같은 키를 쓴다. 프런트는 `encodeURIComponent` 로 감싸서 보낸다.
- **본인 것만 삭제**: 조회 조건이 `user_id = 현재 로그인 사용자` 이므로 다른 사람의 수강 정보는 지울 수 없다.
- **CSRF 보호 유지**: 수강 관리는 실습 페이지가 아니므로 표준 보안 규칙을 따른다. 전역 `CSRFProtect` 가 DELETE 에도 적용되고, `api/client.js` 인터셉터가 토큰을 자동으로 붙인다.
- **404도 "취소된 상태"로 처리**: 다른 탭에서 이미 취소한 경우 서버가 404를 주는데, 프런트는 이를 에러로 띄우지 않고 `enrolled=false` 로 맞춘다. 수강신청의 409(이미 수강 중) 처리와 같은 방식이다.

---

## 6. 난이도(단계) 대신 — 응답별 처리

이 기능은 공격/방어 실습이 아니라 수강 관리 기능이므로, "난이도" 대신 **서버 응답**으로 정리한다.

| 응답 | 조건 | 프런트 처리 |
|---|---|---|
| 204 No Content | 정상 취소 | `enrolled=false`, 버튼 "수강"으로 변경 |
| 401 Unauthorized | 로그인 안 함 | 에러 문구 표시 |
| 404 Not Found | 없는 과목 / 이미 수강 중 아님 | `enrolled=false` 로 동기화 (에러 표시 안 함) |
| 400 (csrf) | CSRF 토큰 만료 | 인터셉터가 토큰 재발급 후 1회 자동 재시도 |
| 그 외 | 서버 오류 등 | "수강취소에 실패했습니다." 표시 |

---

## 7. 핵심 정리

- 수강취소는 **`DELETE /api/v1/enrollments/<course_slug>`** 한 번으로 처리된다.
- 서버는 **출석 세션 → 수강 정보** 순서로 지워 외래키 제약을 지킨다.
- 실습·퀴즈 진도와 보상은 **사용자 기준**으로 저장돼 있어 보존되고, 재수강하면 이어서 진행된다.
- 프런트는 수강 중인 과목에만 버튼을 보여주고, 확인창으로 실수 클릭을 막는다.

  - 다시 "수강" → 목록에 `csrf` 복구, 버튼 "이어하기"로 변경
