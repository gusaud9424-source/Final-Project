# 01. 관리자 비밀번호 변경 · 회원관리

> 대상: 웹 보안을 처음 배우는 입문자
> 목표: "관리자가 회원을 관리하고 자기 비밀번호를 바꾸는" 기능이 프런트·백엔드·DB에서 어떻게 맞물려 동작하는지, 그리고 왜 표준 보안 규칙을 지켜야 하는지 이해한다.
> 작성: 2026-10-03 · 오현명

---

## 1. 요약

- 관리자 페이지(`/admin`)를 **회원관리 · 학생 진도 · 비밀번호 변경** 3개 탭으로 개편했다.
- 회원관리: 학생 목록 조회·검색, **임시 비밀번호 발급**, **회원 삭제**(관련 기록 일괄 정리).
- 비밀번호 변경: **현재 비밀번호 확인** 후 새 비밀번호(8자 이상)로 변경한다.
- 모든 관리자 API는 **관리자 역할 검사 · CSRF · 요청 횟수 제한 · 감사 로그**를 적용했다.
- 백엔드는 새 파일 `backend/app/admin.py` 하나로 묶었고 DB 구조(마이그레이션) 변경은 없다.

---

## 2. 개념 설명 (비유)

아파트 **관리사무소**와 같다.

- 관리사무소는 입주민 명부(회원 목록)를 보고, 이름으로 찾아볼 수 있다(검색).
- 입주민이 열쇠를 잃어버리면 **임시 출입카드**를 만들어 준다(임시 비밀번호). 카드 번호는 건넬 때 한 번만 보여주고 따로 적어 두지 않는다.
- 이사 간 세대는 명부에서 지우고, 그 세대의 택배·주차 기록도 함께 정리한다(회원 삭제).
- 관리사무소 금고 비밀번호를 바꿀 때는 **기존 비밀번호를 먼저 확인**한다(관리자 비밀번호 변경).
- 누가 언제 어떤 일을 했는지는 **업무일지**에 남긴다(감사 로그).
- 관리사무소 문은 **직원(관리자)만** 열 수 있다(역할 검사).

## 3. 용어 설명

| 용어 | 뜻 |
|---|---|
| 역할(role) | 계정 종류. `admin`(관리자) / `student`(학생). 관리자 API는 `admin` 만 허용 |
| 401 / 403 | 401 = 로그인 안 함, 403 = 로그인했지만 권한 없음 |
| bcrypt | 비밀번호를 되돌릴 수 없게 바꿔 저장하는 해시 방식. salt round 12 사용 |
| 임시 비밀번호 | 관리자가 발급하는 10자리 무작위 비밀번호(영문 대·소문자+숫자). 응답에서 한 번만 보여주고 DB에는 해시만 저장 |
| secrets | 파이썬의 암호학적으로 안전한 난수 모듈. 예측 가능한 `random` 대신 사용 |
| CSRF 토큰 | 다른 사이트가 몰래 요청을 보내지 못하게 막는 값. 비-GET 요청 헤더(`X-CSRFToken`)에 자동 첨부 |
| Rate Limit | 같은 IP의 요청 횟수 제한(예: 분당 5회). 비밀번호 대입 공격을 늦춘다 |
| 감사 로그(Audit Log) | "누가·무엇을·누구에게·어디서" 했는지 남기는 기록. `[AUDIT]` 접두어로 서버 로그에 남김 |
| 마스킹 | 화면에 개인정보 일부를 가려 보여주는 것. 휴대폰 `010-****-1234` |

```
 아이디 │ 이름 │ 닉네임 │ 이메일 │ 휴대폰        │ 수강 │ 포인트 │ 가입일     │ 관리
 demo1  │ ...  │ -      │ ...    │ 010-****-1234 │ 5과목│ 149P   │ 2026-09-29 │ [임시 비밀번호][삭제]
```

```
[🔑 비밀번호 변경] 탭
┌──────────────────────────────┐
│ 비밀번호 변경                 │
│ 현재 비밀번호   [          ]  │
│ 새 비밀번호     [          ]  │
│ 새 비밀번호 확인 [          ]  │
│ [       비밀번호 변경       ] │
└──────────────────────────────┘
```

- **회원관리** 탭이 기본이다. 기존 학생 진도 표는 **학생 진도** 탭으로 옮겼다(내용 변경 없음).
- 임시 비밀번호 발급·삭제는 확인창을 거친다. 삭제 확인창에는 "모든 기록이 함께 삭제되며 되돌릴 수 없습니다"를 표시한다.
- 휴대폰 번호는 가운데 4자리를 가려서 보여준다.
- 색은 모두 `var(--sq-*)` 토큰만 사용했다.

### 관련 파일

| 파일 | 역할 |
|---|---|
| `backend/app/admin.py` | 관리자 API 4개 (회원 목록 · 임시 비밀번호 · 회원 삭제 · 비밀번호 변경) |
| `backend/app/__init__.py` | `admin` 블루프린트 등록 |
| `frontend/src/views/AdminView.vue` | 3개 탭 구조로 개편 |
| `frontend/src/components/admin/MemberManagement.vue` | 회원 목록 · 검색 · 임시 비밀번호 · 삭제 |
| `frontend/src/components/admin/AdminPasswordForm.vue` | 관리자 비밀번호 변경 폼 |
| `frontend/src/components/dashboard/StudentsOverview.vue` | 학생 진도 표 (변경 없음, 탭으로 재사용) |

### API

| 메서드 · 경로 | 기능 | 요청 제한 |
|---|---|---|
| `GET /api/v1/admin/users?q=` | 학생 목록(검색: 아이디·이름·이메일) | - |
| `POST /api/v1/admin/users/<id>/reset-password` | 임시 비밀번호 발급 | 분당 10회 |
| `DELETE /api/v1/admin/users/<id>` | 회원 삭제 | 분당 10회 |
| `POST /api/v1/admin/password` | 관리자 본인 비밀번호 변경 | 분당 5회 |

## 5. 동작 원리

### 5-1. 공통 보안 관문

```
요청 ─▶ [CSRF 검사] ─▶ [Rate Limit] ─▶ [로그인 확인] ─▶ [role == admin?] ─▶ 처리 ─▶ [AUDIT 로그]
          실패 400        초과 429         없음 401          아님 403
```

### 5-2. 임시 비밀번호 발급

```
[1] [임시 비밀번호] 클릭 → 확인창
[2] POST /admin/users/<id>/reset-password
[3] 서버: 대상이 학생인지 확인 (관리자 계정이면 400)
      - secrets 로 10자리 생성 (대·소문자·숫자 각 1자 이상)
      - bcrypt 해시로 저장
      - [AUDIT] action=reset_password 기록
[4] 응답에 tempPassword 1회 포함 → 화면 상단 안내 박스에 표시 (복사 버튼)
```

### 5-3. 회원 삭제

```
[1] [삭제] 클릭 → 확인창
[2] DELETE /admin/users/<id>
[3] 서버: 대상이 학생인지 확인
      - 출석 세션(수강에 딸린 기록) 삭제
      - 수강 · 진도 · 보상 · 포인트 · 경험치 · 인증코드 삭제
      - 회원 삭제 → commit
      - [AUDIT] action=delete_user 기록
[4] 응답 204 → 목록에서 즉시 제거
```

### 5-4. 관리자 비밀번호 변경

```
[1] 현재/새/확인 입력 → 프런트 1차 검증 (빈칸 · 8자 · 확인 일치 · 기존과 동일)
[2] POST /admin/password { current_password, new_password }
[3] 서버: 현재 비밀번호 bcrypt 비교 → 틀리면 400
      - 8자 미만 / 기존과 같음 → 400
      - 새 비밀번호 bcrypt 해시로 저장
      - [AUDIT] action=change_own_password 기록
[4] 성공 메시지 표시, 입력칸 비움
```

### 왜 이렇게 설계했나

- **관리자 기능 = 표준 보안**: 프로젝트 지침상 실습 페이지만 의도적으로 취약하고, 관리자·인증 페이지는 CSRF · Rate Limit · 감사 로그를 지켜야 한다. 그래서 4개 API 모두 같은 관문을 통과하게 했다.
- **현재 비밀번호 재확인**: 관리자가 자리를 비운 사이 누군가 화면을 조작해도, 현재 비밀번호를 모르면 바꿀 수 없다.
- **임시 비밀번호는 서버가 생성**: 관리자가 직접 비밀번호를 정하게 하면 쉬운 값을 쓰기 쉽다. 서버가 `secrets` 로 만들고, 화면에 한 번만 보여주며 DB에는 해시만 남긴다. 학생은 이 비밀번호로 로그인한 뒤 "비밀번호 찾기"로 바꾸면 된다.
- **관리자 계정은 보호**: 회원관리 기능은 `student` 만 대상으로 한다. 관리자가 실수로 자신이나 다른 관리자를 삭제·초기화할 수 없다.
- **삭제 시 자식 행 먼저 정리**: `users.id` 를 참조하는 6개 테이블(수강·진도·보상·포인트·경험치·인증코드)과 수강에 딸린 출석 세션을 먼저 지워야 외래키 오류가 나지 않는다.
- **감사 로그는 서버 로그로**: 별도 테이블을 만들면 마이그레이션이 필요하다. 현재 단계에서는 `[AUDIT]` 접두어로 서버 로그에 남겨 `docker compose logs backend | grep AUDIT` 로 확인한다. 비밀번호 값은 로그에 남기지 않는다.
- **휴대폰 마스킹**: 관리자라도 필요 이상으로 개인정보를 보지 않도록 화면에서 가린다.

## 6. 난이도(단계) 대신 — 응답별 처리

이 기능은 공격/방어 실습이 아니라 관리 기능이므로, "난이도" 대신 **서버 응답**으로 정리한다.

| 응답 | 조건 | 프런트 처리 |
|---|---|---|
| 200 / 204 | 정상 처리 | 목록 갱신 · 임시 비밀번호 표시 · 성공 문구 |
| 400 (csrf) | CSRF 토큰 없음/만료 | 인터셉터가 토큰 재발급 후 1회 자동 재시도 |
| 400 | 현재 비밀번호 틀림 · 8자 미만 · 기존과 동일 · 관리자 계정 대상 | 서버 메시지 표시 |
| 401 | 로그인 안 함 | 에러 문구 표시 |
| 403 | 학생 계정으로 호출 | 에러 문구 표시 (라우터에서도 `/admin` 접근 차단) |
| 404 | 없는 회원 | 에러 문구 표시 |
| 429 | 요청 횟수 초과 | "요청이 너무 많습니다. 잠시 후 다시 시도하세요." |

## 7. 핵심 정리

- 관리자 페이지는 **회원관리 · 학생 진도 · 비밀번호 변경** 3개 탭이다.
- 관리자 API 4개는 모두 **CSRF → Rate Limit → 로그인 → 관리자 역할** 관문을 거치고, 변경 작업은 **[AUDIT] 로그**를 남긴다.
- 임시 비밀번호는 **서버가 안전한 난수로 생성**해 **한 번만 보여주고**, DB에는 bcrypt 해시만 저장한다.
- 회원 삭제는 **자식 기록을 먼저 정리**한 뒤 회원을 지우며, 관리자 계정은 대상에서 제외된다.
- 관리자 비밀번호 변경은 **현재 비밀번호 확인**이 필수다.

## 8. 검증

- 백엔드 `admin.py`, `__init__.py` 문법 검사 통과
- 프런트 `AdminView.vue` · `MemberManagement.vue` · `AdminPasswordForm.vue` Vite 모듈 로드(컴파일) 통과
- 브라우저(학생 데모 계정)에서 권한 차단 확인:
  - `GET /admin/users` · `POST reset-password` · `DELETE /admin/users/1` · `POST /admin/password` → 모두 **403**
  - CSRF 토큰 없이 `POST /admin/password` → **400**
- 관리자 계정으로 화면 동작(목록·발급·삭제·비밀번호 변경) 확인은 **확인 필요** (관리자 비밀번호는 seed 시 생성되어 이 세션에서 알 수 없음)
